## 1. 结论摘要

已确认切分 chunk 的全部质量缺陷来自**五级根因的逐级放大**，且已用仓库真实分块代码完成**逐项复现**（书1 拼接 md → 850 块 / 中位 350 字 / 55% 含页码噪声 / 819 个假 chapter，与交接 JSONL 完全一致）。

核心判断：

1. **直接入库的数据（documents.jsonl）不合格**：55.3% chunk 含页码注释、819/850 个 chapter 面包屑不可信、32% chunk <200 字、14 个纯噪声块。
2. **最致命的单点根因是"拼接脚本"**（三路由拼接 + 页码注释注入 + 标题层级推断）——该工序**不在仓库中**，不可复现、不可修复，产出的 assembled.md 是缺陷最集中的载体。
3. **修复起点应为各书的 `*_content_list.json`**（MinerU 块级产物）：结构完整（三本页覆盖率 100%）、自带 `page_idx` 页码溯源、不经过任何污染性中间转换。
4. 书2（1200问）若用当前管线直接切分，将产生**最差**的结果（39% 块 <100 字、面包屑 0% 带章节上下文），必须在重切前完成规范化层建设。

## 2. 管线还原与复现实验

### 2.1 实际管线（经复现锁定）

```

        │（三本书 md 全部为清一色 # 一级标题，无页码标记）
        ▼
[交接方本地脚本]（⚠ 不在仓库，全库检索无 assembled/page: 注入逻辑）

        ▼
assembled.md（书1：695 个页码注释、1096 个多级标题）
        ▼

        ▼
documents.jsonl（850 块，全部缺陷固化）──> 待入库
```

## 5. 修复方案

### P0 新建"解析规范化层"（核心，前置依赖）

新模块建议 `public_kb/normalize.py`（纯函数、确定性、逐书可配），输入 content_list.json，输出规范化 Markdown + 侧车元数据：

- **N1 标题归一化**：按编号体系强制重定级（丢弃 MinerU 的 text_level，只信编号模式）：

  | 模式 | 定级 | 适用 |
  |---|---|---|
  | `第X编/篇` | H1 | 书3 |
  | `第X章`（含书2 分离章号+章名合并） | H1/H2 | 三本 |
  | `第X节` | H2/H3 | 书1/书2 |
  | `中华人民共和国XX法`、`XX条例/规定/办法`（独立成行） | H2 | 书3 法名 |
  | `一、二、` | H3 | 三本 |
  | `（一）（二）` | H4 | 三本 |
  | `N.`（短问题句） | H3（问标题） | 书2 |
  | **不匹配任何编号模式** | 一律降为正文 | 三本 |
  - 反向规则：含句号/问号以外的长句（>40 字且以。结尾）、跨页断句不得成为标题；书3 `第X条` 行拆分为"标题（条号+【条旨】）+ 正文"。
- **N2 目录区识别剔除**：规则 = 正文第一章起始页之前的连续标题区段（书1 页 7–14、书3 `总目录` 区），目录区标题不进 md、不进面包屑。剔除后书1 的 31 组"目录 vs 正文"重复文本自然消失。
- **N3 front matter 剔除**：封面、版权/CIP 页、再版说明、防盗版声明（书3 `本电子版仅限用于…`）。
- **N4 页码溯源**：以 content_list `page_idx` 为准写入每块 metadata（`page_start/page_end`）；**弃用 `<!-- page: N -->` 注释方案**，正文流中不出现任何标记。
- **N5 表格**：table 块提取 caption+footnote 文本入库；表格正文（图片）标记 `content_type=table_image` 待后续专项（全书占比极小，不阻塞）。
- **N6 id 方案**：块 id = `(doc_name, page_idx, page内序号)`（构造性唯一）；入库时沿用 `chunk_ids.py` 的 chunk_uid，但 metadata（doc_name/chapter/chunk_index）必须完整，禁止缺省派生。
- **N7 OCR 抽检**（书2/书3）：随机 20 页对照原 PDF 人工核对字符错误率；超阈值（如 >0.5%）的书考虑走云端重解析或全文 LLM 校对专项。

### P1 TextCleaner 增强兜底

- 剥离 HTML 注释并转 metadata（防御性兜底，防止任何上游再注入）；
- 保留现有页眉页脚/页码/短行规则不动。

### P2 SemanticChunker 增强

- **S3-1 修复**：增加最小块合并——相邻同章节 <min_chars（建议 200）的小节向后合并，直至接近 max_chars；
- **S3-2 修复**：层级栈策略改为"编号标题按归一化级别入栈；无编号降级文本不触碰栈"，杜绝面包屑清空；
- **S3-3 修复**：chunk_index 改为章内递增并保证 (chapter, index) 唯一，或全局递增；
- **S3-4 新增**：Q&A 绑定模式（书2）——问题标题与其下答案合并为单一检索单元（上限仍 2000 字）；
- **新增**：面包屑前缀注入——chunk 文本头部拼接 `【{chapter}】`（提升 dense/BM25 对章节词的命中，引用展示同步受益）。

### P3 入库前校验门禁（硬闸，不合格即拒绝入库）

新增 `public_kb/handoff_validate.py` + pytest 用例，准入清单：

1. 含 `<!--` 的 chunk 数 = 0；
2. <100 字 chunk 占比 ≤ 2%（且无纯标记/纯空白块）；
3. unique(chapter) ≤ 归一化后真实章节数 × 1.2；
4. 面包屑含章节上下文的占比 ≥ 80%（书2 按问标题口径单列）；
5. metadata 页码覆盖率 = 100%；
6. 标识唯一性与确定性（引用溯源 R1/R2 的前提）：
   - 结构 id `(doc_name, page_idx, 页内序号)` 构造性唯一，0 冲突；
   - 每块携带 chunk_uid，格式 `ck-<32hex>`，存在率 100%；
   - chunk_uid 全库冲突 = 0（跨三本书统一口径；以第 3 项 chunk_index 章内唯一为前提——`chunk_uid = md5(doc_name|chapter|index|text_hash)`，index 不唯一则同章节同文本必撞）；
   - **确定性**：同参数重跑两次切分，chunk_uid 全集逐项一致（路径 A/B 两条入库契约、跨集合重建引用口径稳定的基础）。
7. 目录区/front matter 块数 = 0（按 N2/N3 识别口径复查）。

### P4 重切与入库流程（对齐 2026-09-01 D 决策）

1. P0 规范化层 + 单元测试（用三本书真实 content_list 做夹具）→ P1/P2 增强 → P3 门禁；
2. 三本书重切 → 每书人工抽检 30 块（重点：面包屑正确性、问答/条文完整性）；
3. `scripts/run_knowledge_citation_eval.py` 引用评测回归（chunk_uid/page 溯源口径已变，评测侧同步适配）；
4. 通过 P3 门禁后重建 Milvus `public_kb` 集合（D3 零降级：重建期间检索不可用窗口提前公告；schema 仍要求 sparse+BM25 fail-fast 校验）；
5. 交接产物重新导出，交接 README 的三个 CLI（`--ingest-jsonl`/`--ingest-markdown`/`--prepare-handoff`）随本次一并实现，杜绝"仓库外工序"。

### 不改动项（决策对齐）

- 模型身份配置仍 .env-only（D4/D6）：embedding/reranker 不因重切变更；
- 检索链路零降级（D3）：不因数据重建引入任何 fallback；
- 已入库的无效存量数据本轮不动（重切分专项统一重建）。
