## 2. 实证问题清单

### P1 router 单次失败即放弃，瞬时错误零容忍（`router.py:225-242`）

- 结构化输出路径失败后，仅当错误信息包含 `response_format / unavailable / not supported` 三个关键词才切换 Tool Calling 重试一次；**其余一切异常（429 限流、超时、JSON 解析失败、网络抖动）直接 raise → fallback**。
- 实测：37/38 的 fallback 样本耗时中位数仅 9 秒 = 一次正常 LLM 调用后即放弃，无任何重试。这与口径 B（同配置原样重发允许，重试耗尽才失败）的精神相悖——router 是全链路第一个 LLM 调用点，却是最脆弱的一个。
- 影响：一次偶发 429/超时 = 用户问题直接得到兜底话术。

### P2 fallback 语义过宽：模型被邀请"选 fallback"，且与异常兜底混同

- 提示词明确引导："**不确定时用 route_fallback**"（`ROUTER_USER_TEMPLATE`），且 fallback 是 5 个 tool 之一（`tool_choice="required"`）——模型面对长句/生僻措辞时倾向于选择 fallback 而非尽力分类。
- 异常兜底与模型主动选择 fallback 走同一条出口（`{"router_intent": "fallback"}`），**日志无法区分"模型选的"与"崩了"**（前者 info，仅异常才 error/warning）——本次测评因此无法归因 38 题 fallback 的真实构成。
- 影响：条款号直查类（含《书名》+ 条号 + 括号注释的长句）16/28 被放弃，其中相当比例按提示词定义本应稳定归入 knowledge_qa。

### P3 doc_qa 误路由：概念阐释类 29/30 全灭

- 概念阐释题形如"关于「二、对"招标投标"概念的理解」，资料中是如何说明的？"：17 题误入 doc_qa（placeholder 分支，无实际能力，等于黑洞）+ 12 题 fallback，仅 1 题到达 knowledge_qa。
- 诱因假设（待日志确认）：① 题面含"资料""说明"字样，模型联想"文档问答"；② 嵌套引号「二、…」编号触发歧义；③ doc_qa 描述"上传文件后要求分析、解读、对比文档内容"与题面"资料中说明"边界模糊。
- 影响：即便修复 P1/P2，这类措辞仍会被系统性误路由。

### P4 超时管控存在逃逸路径（1 题 6.9 小时）

- 配置明文：`LLM_TIMEOUT=60s`、`NODE_TOTAL_TIMEOUT=45s`，但实测出现 **24910s（6.9 小时）** 的单题挂起。
- 说明至少一条调用路径（疑似 router 的 structured_output 或工具调用链）未真实生效超时，或超时后重试无限累积。6.9h ≈ 60s × ~400 次的量级，指向"超时配置未传导 + 无总时长闸门"的组合缺陷。
- 影响：单条用户请求可挂起数小时，占用并发额度（`LLM_MAX_CONCURRENCY=8`）。

### P5 可观测性与结构性隐患

- **决策不可归因**：路由结果无结构化日志（intent 之外的 reason/路径/耗时/异常类型未落盘），事后无法区分 P2 的两种 fallback；
- **构建期预检测烧真实调用**（`router.py:203-212`：`test_llm.invoke("测试")`），且其失败分类关键词与运行时相同（3 关键词），误判即单向门锁死整个会话的路由方式；
- **同步/异步四份重复实现**（`_route_via_structured_output` / `_route_via_tool_calling` × sync/async），fallback 逻辑各自维护，已现漂移风险（同步版预检测 + 异步版无预检测）。

## 3. 排查计划

### 阶段 0：可观测性补齐（先行，半天）——没有它后续全是盲猜

| # | 动作 | 产出 |
|---|---|---|
| 0.1 | router 决策结构化日志：intent、reason、路径（structured/tool/fallback）、异常类型摘要、耗时，落独立日志文件 | 可归因的路由日志 |
| 0.2 | 评测脚本采集路由日志（按 sample_id 关联） | 104 题的逐题路由归因 |
| 0.3 | 用现有 104 题结果 + 日志重放 10 个 fallback 样本（同 thread_id 不需要，直接复跑单题） | fallback 构成分布：模型自选 vs 解析失败 vs 瞬时错误 vs 超时 |

**阶段 0 验收**：能对任意一题回答"它为什么进了 fallback"。

### 阶段 1：定位确认（1 天）

| # | 假设 | 验证方法 |
|---|---|---|
| 1.1 | 条款号直查的 fallback 是"结构化输出解析失败"还是"模型自选 fallback" | 阶段 0.3 归因分布 |
| 1.2 | 6.9h 挂起的具体路径（structured_output？tool calling？重试累积？） | 复现该题 + 打点每层耗时；核查 `llm_timeout` 是否传入 `ChatOpenAI`（`llm_factory.py:47` 已传，需验证 OpenRouter 端是否吞掉超时） |
| 1.3 | doc_qa 误路由是提示词问题还是分类能力问题 | 用 30 个概念阐释题做路由单测（脱离全链路，直接调 router），改提示词做 A/B |
| 1.4 | 预检测的必要性 | 移除预检测后全量评测对比（首次真实失败再切换 vs 预检测） |

### 阶段 2：修复（1-2 天，方案需评审拍板）

| # | 修复项 | 对应问题 | 口径依据 |
|---|---|---|---|
| 2.1 | **重试策略**：瞬时错误（429/超时/网络）同配置退避重试 2 次；解析失败重试 1 次；仅支持性错误切换 Tool Calling；耗尽才 fallback | P1 | 口径 B |
| 2.2 | **超时加固**：router 专用超时（建议 30s，独立于 `LLM_TIMEOUT`）；核查 6.9h 逃逸路径并加节点级总时长闸门 | P4 | 操作参数 |
| 2.3 | **提示词修订**：doc_qa 触发条件收紧为"明确提及上传文件/指定文档对象"；新增"资料/规定中如何说明"类 → knowledge_qa 正例；fallback 措辞改为"完全无法判断时才使用" | P2 P3 | — |
| 2.4 | **（需拍板）fallback 补救规则**：fallback 后做一次轻量规则路由（含《》/第X条/法规关键词 → knowledge_qa），避免知识类问题直接死于兜底话术。定性：路由层的意图补救，非检索降级，不违背 D3 | P1 P2 | 需评审 |
| 2.5 | **预检测治理**：移除构建期预检测（省一次调用、消除单向门误判），改为运行时惰性切换；同步/异步逻辑收敛为单一实现 | P5 | — |
| 2.6 | **决策日志**：保留阶段 0 的结构化日志作为常驻能力 | P5 | — |

### 阶段 3：回归验证（半天）

复跑同一 104 题测试集（`--no-resume`），验收标准：

- [ ] knowledge_qa 到达率 ≥ 90/104（现 41）；
- [ ] fallback ≤ 5，且每条可归因（日志）；
- [ ] doc_qa 误路由 ≤ 2；
- [ ] R1–R7 通过率保持 100%（不得因路由修复引入引用质量回退）；
- [ ] 平均耗时 < 60s/题，无 >5 分钟离群；
- [ ] 拒答负样本中进入 knowledge_qa 的题目（预期部分会进入）拒答行为正确（`is_refusal=true` 或语义拒答）。

## 4. 拍板点（进入阶段 2 前需确认）

| # | 决策项 | 建议 |
|---|---|---|
| Q1 | 是否引入 fallback 后的规则补救路由（2.4） | **建议引入**：纯提示词修复无法保证到达率，规则补救只针对明显知识类特征，代价小收益大 |
| Q2 | router 专用超时值（2.2） | 建议 30s（当前 60s 但被逃逸；路由是轻任务，30s 足够） |
| Q3 | 重试次数（2.1） | 建议 transient ×2 + 解析失败 ×1，全部口径 B 语义 |
| Q4 | 同步/异步收敛方式（2.5） | 建议本次一并收敛为单一实现 + async 包装（四份漂移是长期隐患）；若工期紧张可仅同步修复、登记技术债 |

## 5. 不改动项

- 检索链路（qa_chain / milvus_store）不动——已实测满分；
- D3 零降级口径不变：router 的 fallback 是"意图未定时的用户引导"，不属于检索链路内部的静默质量降级；但**本次要消灭的是"本可到达却被误杀"的部分**；
- `temperature=0` 保持。

## 6. 风险

| 风险 | 对策 |
|---|---|
| 重试引入延迟放大（3 次重试 × 60s） | router 专用 30s 超时 + 重试仅对瞬时错误；总时长闸门兜底 |
| 提示词修订影响其他类别的分类准确率 | 阶段 3 全量复跑对比，任一类别到达率回退即回滚提示词 |
| 规则补救路由误吞（把 price_inquiry 问题拉进 knowledge_qa） | 规则只含法规特征（《》、第X条、招标/投标/评标术语表），不含企业/项目查询特征；复跑验证 price_inquiry 题目不回归 |
| fallback 题重放时结果不可复现（LLM 非确定性） | temperature=0 + 重放取 3 次多数投票做归因统计 |
