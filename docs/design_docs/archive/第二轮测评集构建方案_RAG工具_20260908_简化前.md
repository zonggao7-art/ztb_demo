## 3. 固定原文，明确“旧对照”代表什么

### 3.1 当前三本书

| 编号 | 书籍 | 当前本地新切分产物 |
|---|---|---|
| book1 | 招标投标法律解读与风险防范实务 | 316 块，中位 1,719.5 字符 |
| book2 | 政府采购、工程招标、投标与评标1200问（第3版） | 161 块，中位 1,884 字符 |
| book3 | 中华人民共和国招标投标法律法规全书：含相关政策 | 443 块，中位 1,903 字符 |

PDF 位于 `raw_pdfs/`；对应 MinerU 解析材料位于 `DATA/raw_data/`；新切分产物位于 `DATA/repaired_knowledge/book1|book2|book3/`。本地 JSONL 合计 920 块，manifest 记录的切分参数为 `max_chars=2000`、`min_chars=200`、`overlap_chars=100`。

这些是本地文件事实，尚未据此核验实验 Milvus 集合内容。现有 manifest 的 `source_path` 仍指向原项目路径，实施时应另建副本来源清单并核对文件哈希，不能直接沿用旧绝对路径执行写入。

### 3.2 先冻结到哪一层

冻结清单至少记录：三份 PDF 的版本信息和 SHA-256、解析输出的 SHA-256、解析器版本/配置、旧新处理代码版本及未提交补丁、清洗/切分参数、产物哈希。

**建议先以同一批 PDF 和同一份未经新治理的解析输出作为两组共同输入。** 这样主要观察规范化、清洗、切分与嵌入的组合收益。新 `normalized.md`、新 chunk 和新生成的面包屑不能充当旧组的共同起点，否则旧组已获得部分新治理收益。

这只是建议，尚有一个边界需要核定：如果旧流程本身包含不同的 PDF/OCR 解析，则决定把解析差异纳入“数据治理”，还是固定解析输出。无论选哪种，两组都应追溯到同一版本 PDF，并在报告中明确比较起点。

### 3.3 旧组必须能够说明来源

“旧组”在本实验中指**旧处理方式在当前三本书上的重建基线**，不等同于第一轮当时运行的完整系统。

重建前需要找出旧清洗、切分、标题/问答处理、重叠、去重和元数据构造逻辑，确认旧嵌入模型的确切标识、维度及查询编码方式。旧题源片段中位长度 68 字符，不代表旧算法的 chunk_size 就是 68，也不能直接设一个小 chunk_size 来冒充旧流程。

若旧实现或旧模型无法恢复，应把缺失项、替代规则和预期偏差交由用户决定。采用替代方式后标成“近似重建基线”，报告不得称为精确复现第一轮。

**可答性以共同原文为准。** 如果一组清洗丢失了原文证据，这本身属于被测处理链的损失，应保留该题并记录丢失，不能只保留两组 chunk 都完整包含答案的题。题目也不能因为某组检索失败而被移出正式集。

## 4. 标准依据的组织方式

### 4.1 三层分开保存

| 层次 | 保存内容 | 为什么需要 |
|---|---|---|
| 题目与答案要点 | 独立完整的问题、适用条件、参考答案、必须答出的要点、错误边界 | 决定题目要求系统做什么 |
| 原文证据 | 书籍/版本、页码、条款或问答编号、原文片段、证据编号 | 不随 chunk 切分而改变的评分基准 |
| 各组映射 | 每条原文证据在旧组、新组分别对应哪些 chunk、哪些区间，是否完整保留 | 解释哪一阶段找到了或丢失了证据 |

原文证据应覆盖决定答案的条件、例外和限制，不能只截取一个结论词。一个“证据单元”指支持一项必要判断的最小充分原文，可以包含相邻数句。

定位时保存 PDF 文件页序与纸面页码的区别：建议 `pdf_page` 统一用从 1 开始的文件页序，`printed_page` 独立保存。当前产物的 `page_start/page_end` 与 `page_number` 有不同基数，转换时需显式记录。

`normalized.blocks.jsonl` 的 `source_ordinal`、chunk 的 `source_ordinals` 可以辅助映射，但它们依赖解析产物；必须同时保存来源快照和原文定位。规范化文本用于搜索和阅读，疑似 OCR 错误、关键数字及版本信息应回查 PDF。

### 4.2 同一证据允许不同承载形式

例如一道抽象题必须回答要点 A 和 B：旧组可能分别放在旧块 12、13，新组可能都放在新块 8。两组只要提供了 A、B 的完整依据，就应获得相同的证据覆盖分。

映射允许一对多和多对一：一个证据可能跨多个块，多个证据也可能位于同一块。重叠内容或不同 ID 的重复正文不重复记分。若一条证据被拆开，只有实际返回片段的并集足够支持该要点，才能判定完整覆盖。

对于同一判断在不同书中存在同等充分的依据，可以登记多个替代证据组合。例如 `(E1 且 E2) 或 E3`，返回其中任意一组完整组合即可。不能要求检索所有重复表述，也不能把不同制度、版本或适用条件下的相似语句误当作替代证据。

映射应先对两组完整切分产物进行，不能只搜索当前检索器已经返回的结果。模糊匹配只提出候选，关键条件是否保留需审核；运行时发现新的有效依据，应按统一规则复核并同步重评所有组。

## 5. 首批 30 题怎样选

以下配比是**试标建议**，用于尽早暴露标注问题，不代表真实用户请求分布，也不构成正式题集配比承诺。

| 主类型 | 建议数量 | 判定依据 |
|---|---:|---|
| 单证据可答 | 16 | 一个最小充分证据即可支持完整回答 |
| 多证据可答 | 9 | 必须组合至少两项不同证据才能完整回答 |
| 不足以给出确定结论 | 5 | 三本书确无所需信息，或题目缺少不可省略的前提 |
| 合计 | 30 | 全部进入试标/开发用途 |

9 道多证据题建议至少涵盖“并列汇总”和“条件判断/例外适用”两类。只有后者存在真实依赖关系时才标记为分步推理；并列问两个问题不能自动视为推理多跳。原始单跳/多跳标签可保留为历史字段，二轮按证据需求重新标注。

每题另设可重叠标签：

- **问法**：原文术语、日常表达、情境化提问。既保留精确术语检索，也覆盖不直接照抄原文的问题。
- **任务**：事实/条件、程序/步骤、期限/数字、比较辨析、例外适用。
- **潜在处理难点**：长条文、问答绑定、标题和正文关系、跨段依据、相似制度干扰、OCR 疑点。
- **来源**：主来源书、涉及书籍及章节；多书依据单独列出，避免重复计入书籍配额。
- **预期行为**：直接回答、有限回答并说明边界、请求补充条件、说明资料不足。

三本书都应有实质覆盖，建议 25 道可答题中每本至少有 5 道以该书为主来源，其余按主题缺口分配。跨书题必须确实需要跨书依据，不能为了凑配比拼接无关法规。试标不强制穷尽所有标签组合。

切分边界属于实验结果而非题型定义。应先按原文选题，再根据两组映射补充“旧组跨块/新组同块”等诊断标签，避免专挑新切分恰好占优的位置作为代表性样本。针对已知故障刻意设计的题，标为挑战样本并单列成绩。

### 5.1 候选题的来源

以三本书的原文单元为主，从不同章节和任务类型选题；旧 200 题及旧失败案例用于补充问法和错误模式。最终每题都必须重新建立三本书中的依据，不规定必须复用多少道旧题。

对于模型辅助出题，先给模型经过定位的原文证据包，再要求生成问题、答案要点和证据对应关系；不直接按新 chunk 每块造题。建议先形成 40～50 道候选，审核后择取 30 道，以免为达到数量保留坏题。这是候选量建议，是否采用模型、具体模型和费用仍待确定。

### 5.2 不足以回答的题要怎样标

建议 5 题中覆盖“资料范围内没有答案”和“缺少决定性前提”，明确合理行为是否允许有限回答。领域相关但缺少关键事实的题，比单纯问天气更能检查 RAG 边界。

不能因为某次 Top-K 没召回而标记“不可答”。标注资料缺失时，应检查三本书目录、同义词、相关段落和可能的替代依据，并保存搜索范围及审核说明；无法确定时记为待审。

错误前提不一定要求拒答：如果原文足以纠正前提，应标为“可答并纠正”。资料没有提到某事，也不等于可以断言某事不存在。不能通过给某一组人为删除关键 chunk 的方式，制造本组专属拒答题。

## 6. 参考答案和人工审核

### 6.1 每题先完成一张审核卡

| 必填内容 | 审核问题 |
|---|---|
| 问题和情境 | 脱离出题上下文能否独立理解？有没有“上述案例”“资料 2”等悬空指代？ |
| 适用范围 | 属于哪种制度、哪类项目、哪一资料版本？条件是否足够？ |
| 必答要点 | 哪些信息缺失会导致回答不完整？每个要点是否可独立判断？ |
| 原文依据 | 每个要点能否定位到完整、充分的原文？ |
| 参考答案 | 是否覆盖必要条件、数字、例外，而不引入证据之外的结论？ |
| 可接受差异 | 哪些等价表达、不同顺序或补充说明可以接受？ |
| 不可接受内容 | 哪些范围混用、数字错误、遗漏例外或无依据推断构成错误？ |
| 预期行为 | 应回答、限定回答、澄清还是说明资料不足？ |
| 审核记录 | 谁审、何时审、修改了什么、最终是否通过？ |

参考答案不要求唯一措辞，应保留简洁完整的答案和可独立核对的要点。每个要点至少关联一组充分证据，避免先写答案再找相似段落充当依据。

模型可以生成和检查草稿；30 题的最终参考答案、可答性与证据边界均需人工逐题审核。由用户掌握最终通过/退回决定，助手承担定位、整理、查重和格式校验。机器自检通过只标记为“待人工审核”。

审核可按 10 题一批交付；先用少量题对齐“完整/部分/错误”的判定口径，再按同一口径复核此前题目。对模棱两可、版本冲突或证据不充分的题，先修订或排除并记录原因。

### 6.2 法规书籍的时间范围

本阶段默认评价**基于冻结书籍资料的检索和回答能力**。资料中的版本、适用条件及引用关系必须正确，不能把书中历史表述自动包装为截至今天的现行规则。

涉及可能随时间变化的内容，应在题目中明确资料版本/时间范围；涉及不同书籍表述冲突时，不能让裁判自行挑一个答案作为真值。需要评价现行法规正确性的题，应另做权威来源核验并决定是否更新共同资料源，再进入正式集。本次方案没有完成法规现行性审核。

| `evidence_requirements` | 每个要点的必要证据与可替代组合 |
| `unanswerable_reason`、`absence_check` | 非完整可答题的原因及核查记录 |
| `review_status`、`reviewer`、`reviewed_at` | 人工审核状态和时间 |

### 7.2 证据和映射记录

证据目录保存 `evidence_id`、`source_id`、`source_version`、`pdf_sha256`、页码/条款/问答编号、原文引用、核验状态。清洗文本及其字符区间可以作为辅助定位，但必须注明文本快照版本。

映射记录保存 `evidence_id`、实验组、chunk 产物哈希、chunk ID/UID、块内证据区间、完整/部分/丢失状态及审核依据。ID 建议按字符串序列化，避免旧 Milvus 大整数 ID 在部分工具中发生精度损失。

尚未建旧组时，旧映射可为空并注明“待重建”；不得预填虚构 chunk ID。原文真值可先建设，依赖实验产物的映射在产物固定后补齐。

### 7.3 Ragas 输入与实际运行结果

内部题目、原文证据和运行结果分开保存，再由适配层转换为选定 Ragas 版本要求的字段。概念对应为：问题 → `user_input`，实际回答 → `response`，该组实际送入回答模型的文本列表 → `retrieved_contexts`，审核答案 → `reference`；确切 API 名称和要求以最终安装版本为准。

**标准证据不能替代实际检索上下文传给 Faithfulness。** 回答模型只能看到问题及该组实际上下文，不能接收参考答案、答案要点或标准证据目录。直接提供标准证据的实验只能标作额外的生成诊断，不计入正常 RAG 成绩。

## 8. 指标如何由这份题集支撑

### 8.1 检索主指标：按证据要求统计

对每题，将必须满足的证据要求拆成可独立判断的若干项。某项只有在返回片段合起来满足一组充分依据时才记为覆盖；替代依据不增加分母，重复文本不增加分子。

`证据覆盖率 = 已满足的必需证据项数 / 全部必需证据项数`

`证据齐全 = 该题所有必需证据项均已满足`

总体证据覆盖率按题取平均，证据齐全率为齐全题数除以适用的可答题总数，同时按来源、题型和难点分组。这是本项目的证据覆盖口径，不应直接命名为某个 Ragas 官方指标。

| 指标 | 需要保存什么 | 解释什么 |
|---|---|---|
| 原文证据保留率 | 原文证据在整份切分产物中的完整映射 | 处理阶段是否先把资料丢掉了 |
| 候选证据覆盖/齐全率 | 过滤前候选及顺序，初始候选上限参考总方案 30 | 是否进入检索候选池 |
| 过滤前 Top-K 覆盖/齐全率 | 按当阶段排序取前 K 的完整文本，主要看 K=5，可补 K=1/3 | 前列排序是否提供足够依据 |
| 最终上下文覆盖/齐全率 | 过滤及上下文预算截断后，实际送入模型的文本 | 模型实际能看到多少依据 |
| 阶段证据损失 | 相邻阶段已覆盖证据项的集合差 | 分清排序截断、阈值过滤、上下文截断造成的损失 |
| 重复片段占比 | 返回数与按冻结规则合并的独立正文数 | 上下文是否被重复内容占用 |

重复片段占比可先采用 `1－独立正文数/返回片段数`，空返回记为不适用；精确重复和经审核的近似重复分开记录，不把“同书/同章节”视为重复。原始检索结果仍须保留，离线统计去重不能悄悄改变实验输入。

不把旧 ID 命中率作为跨切分主指标。若后续采用 Context Precision、MRR 或 nDCG，先决定相关性等级、候选标注范围及重复依据处理，不能因为返回的大块碰到一句答案，就将整块视为完全相关。首批不为这些可选指标额外展开大规模标注。

不同块长意味着相同 Top-K 不等于相同信息量。两组采用相同上下文 token 上限、相同截断规则和计数方式，并记录实际 token。证据覆盖提升应与 token/耗时一起解释；不足上限的组不人为填充无关资料。预算数值在试跑前确定。

### 8.2 回答指标：沿用三项 Ragas，补上人工可核对的内容

| 指标 | 评分对象 | 所需资料 |
|---|---|---|
| Faithfulness | 回答是否受到该组实际上下文支持 | 回答＋实际上下文 |
| Answer relevancy | 回答是否围绕问题、回应需求 | 问题＋回答，以及所选版本所需的固定裁判/评分嵌入配置 |
| Answer correctness | 回答与审核参考答案是否相符 | 问题＋回答＋参考答案，以及固定评分配置 |
| 要点完整与错误记录 | 必答条件是否遗漏，是否出现关键错误 | 人工审核卡、实际回答与证据 |
| 引用支持情况 | 被引用文本是否支持对应结论 | 回答中的论断及其实际引用 |

Ragas 的实现版本、裁判模型、评分用嵌入模型、提示词/权重、重试和超时配置均应固定。**评分用嵌入模型与被测检索嵌入模型是两个角色，不能随着实验组变化。** 低温度有助于控制波动，但不能宣称模型裁判完全确定。

三项分数分别报告，不合成一个未经定义的“准确率”；0.75 分不能表述为 75% 的题答对。试标时人工逐题查看分数与审核卡是否一致，发现分歧先检查标准答案和裁判口径。

现有 `CitationValidator` 的 R1–R7 检查标识、原文/来源字段、标记及上下文覆盖等结构条件。它们不能替代“某个法律判断是否有充分支持”的语义审核，也不能证明内容现行有效。

Ragas 版本在总方案中尚未确定，本次也未完成依赖安装或适配验证；尝试读取官方文档时工具返回 404。以上是指标目的和内部数据约定，具体 API、默认权重及各类输入的可评分性需要在副本环境用小样本确认，不能预先声称已跑通。

### 8.3 可答性、失败和分母

每题分开记录 `execution_status`（成功/超时/工具错误/空输出等）与 `response_behavior`（回答/限定回答/澄清/拒答），再对照题集中的预期行为判断是否合适。接口返回成功不等于回答正确。

- 可答题：检索未覆盖证据记为检索失败；错误拒答计入误拒答。运行失败、空答案在全量结果中保留。
- 不足以给出确定结论的题：检查是否正确说明边界、请求所缺条件，或给出允许的有限回答；另外记录无依据确定作答。
- 没有必需正向证据的题：证据覆盖率不适用，不以空集合得到 100% 召回来奖励。
- Ragas 对特定空值/拒答输入无法有效评分时，保存空值、原因和 `score_failed`，不能把“无结果”悄悄当作有效零分或有效满分。
- 报告每项分数的有效评分数/应评数、失败/缺失数；另报面向全部题目的完成和行为结果。

新旧组按固定 `sample_id` 配对。质量分可在双方均得到有效评分的题目上比较，但同时必须展示固定全量题集的失败及行为情况；不能只取成功题交集就宣布整体提升。

### 8.4 时延和成本

运行结果保存查询嵌入、检索、重排、回答及总耗时；检索独立实验不统计不存在的生成 TTFT。若运行回答流，区分首个有效答案 token 与进度提示。

费用拆为一次性处理/建库、题目生成、实际问答、Ragas 评分，分别记录输入/输出 token、接口计费信息或估算方法。定价和模型选择未确认前不填写固定金额预算；先由试跑得到单位成本，再请用户决定扩容。

30 题仅足以检查标注与实验流程，并提供初步现象。可展示均值、P50、P95，但需附样本数；小样本尾部分位数不稳定，不据此作确定的生产时延或微小涨分结论。正式扩容后再考虑按题族配对的置信区间及分层分析。

## 9. 这份题集怎样支持后续检索实验

全阶段使用同一题目版本、原文真值和答案标准；各组保存自己的映射和实际上下文。

| 阶段 | 对照方式 | 题集主要用途 |
|---|---|---|
| A：组合改造 | 旧处理＋旧嵌入 / 新处理＋新嵌入，均为稠密检索 | 证据是否保留、是否召回、答案和代价如何变化 |
| B：加入关键词融合 | 固定新数据/新嵌入，对比增加 BM25＋RRF 前后 | 原文术语、相似表达、多证据题的候选覆盖 |
| C：加入重排 | 对比同一候选形成方式下增加重排前后 | 前列证据的齐全程度、干扰片段与重复情况 |
| D：调整过滤 | 在同一种重排分数上比较固定与动态规则 | 误过滤、误拒答与无依据作答的变化 |

0.45 仅是总方案记录的旧稠密阈值依据，旧模型核实后才成为冻结实验配置；融合分、重排分不能直接套用它。不同嵌入模型即使共享数值阈值，过滤强度也未必相同，故 A 阶段必须同时保存过滤前结果。各组阈值若需调参，只能在开发题上完成，并作为另一份明确配置报告。

建议先完成所有组的检索统计，再由用户根据结果决定哪些中间组值得生成答案和运行 Ragas。初始新旧组与选定最终组需要完整回答结果；生成时不能沿用第一轮上下文。

## 10. 构建流程和每次交回用户的材料

| 步骤 | 助手承担的机械工作 | 交付与用户决策 |
|---|---|---|
| 1. 确认资料和旧处理起点 | 核对三本书与解析文件哈希，找旧处理代码/参数/模型证据 | 来源清单、旧实现可恢复/缺失项；用户确认解析差异是否纳入及替代方案 |
| 2. 建立原文证据包 | 按章节找证据，定位页码/条款，整理候选主题和旧题改写可能性 | 少量示例审核卡；用户校准题目范围和标注口径 |
| 3. 形成候选并试标 | 生成/整理候选、查重，按建议题型配比编排，逐题补齐依据 | 每批约 10 题；用户审核参考答案和预期行为 |
| 4. 冻结试标 30 题 | 修订退回题、检查结构、保存审核日志与题集哈希 | 30 题及覆盖表、问题清单；用户确认首批题集可进入试跑 |
| 5. 补齐两组证据映射 | 在两组产物上定位证据，记录完整/部分/丢失及替代关系 | 映射差异报告；丢失证据作为实验结果保留 |
| 6. 小样本验证评分 | 在另行确定实验配置后运行少量检索/回答/评分，核对字段、耗时与费用 | 裁判分歧、失败记录、每题成本；用户决定正式规模及预算 |

每阶段交付后保留用户的判断机会，不从方案自动推进到业务改造、全量生成或实验建库。本次授权工作的交付物是本文；后续实际构建按照用户确定的步骤推进。

试标 30 题一旦用于改写提示词、调整阈值或评分口径，就永久属于开发资料。正式扩展时另留未参与调参的测试题，按证据/案例题族划分，避免同一法条的近似问法分别进入开发集和测试集。

这不要求把测试题所需原文从知识库中移除：RAG 测试本来就需要在库内找证据。隔离的是调参接触过的题目及高度相似变体。正式测试发现标注错误时，保留修订记录并对所有组统一重评，不只修改不利于某组的题。

## 11. 首批验收与仍待讨论的事项

首批 30 题应满足以下条件，才算“试标完成”：

- 题号唯一、题意独立完整；精确重复已消除，同证据变体已用题族归组。
- 三本书和主要题型都有覆盖，报告实际分布及尚未覆盖的主题。
- 所有可答题的每个必要要点均有可定位且人工认可的原文依据。
- 所有不足以回答的题均有原因、核查记录及明确预期行为。
- 参考答案没有悬空的“资料 1/2”引用，范围、版本、条件和数字已核对。
- 30 题均有人工审核结果；未决题先退回候选池，不假装已经通过。
- 题集、来源和审核记录已冻结版本；旧新映射尚未完成的部分如实标记。

这表示题集适合进入试跑，不表示 RAG 质量已经通过验收。两组映射与实验配置未齐备时，也不能把候选题或未跑通的评分当作正式成绩。

已经确认：以三本书为共同原文、重建旧处理对照、先做 30 题。

接下来需要讨论的事项按依赖顺序为：

1. **旧处理方式的准确范围和可恢复性。** 先找旧版本及参数证据，再判断是否需要近似重建；同时确定 PDF/OCR 解析是否纳入变量。
2. **试标题型与资料时间范围。** 确认是否采用 16 单证据＋9 多证据＋5 边界题，以及基于书籍版本回答的口径。
3. **生成与评分配置。** 确定出题模型/方式、回答模型、裁判、评分嵌入、Ragas 版本、上下文预算和首批费用上限。
4. **扩容。** 在 30 题审核与试跑之后，由用户根据覆盖缺口、人工耗时和单位费用决定正式题数。

建议下一次只推进第 1 项：提交旧流程的证据和缺失清单，供用户判断对照组能否按原计划重建。
