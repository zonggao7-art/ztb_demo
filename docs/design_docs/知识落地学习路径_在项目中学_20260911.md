## 2. 为什么不能按总纲 §19 的顺序学

总纲 §19 给了"六个面试准备单元"，但它是**按章节切的**：

- 单元 3 让你学 §6、§10 —— 此时你手上还没有前端，"不同源"到底卡在哪你体会不到；
- 单元 4 让你学 §8 —— 你还没跑过一条流，"要取消什么"是抽象的；
- 单元 5 让你学 §12 —— 飞书权限没配过，"权限 / 事件 / 范围"三个词背得下来，但分不清。

章节顺序是**知识组织的顺序**，不是**认知发生的顺序**。结果是：读完很爽，一周后全忘，因为没有任何一条被真正"用掉"。

改成**卡点驱动**：

> 每条知识点的最佳学习时机 = 它第一次让你动手失败的那个瞬间。

CORS 是这样学会的：你写完 fetch，页面一片红，控制台报 `blocked by CORS policy`。这一刻你去看 §10.4，一辈子忘不掉。先看文档再看现象，反而记不住。

## 3. 通用学习循环（每个知识点都走这五步）

```text
1. 预测   动手前，先写下你认为会发生什么
2. 动手   跑一次，拿真实输出
3. 观察   输出和你预测的差在哪
4. 解释   用一句话解释"为什么是这样"
5. 复述   合上文档，讲给空气听（面试就是这个动作）
```

**第 1 步是全流程里最值钱的，也最容易被跳过。** 预测错了的地方，才是你真正要学的地方；预测对了的地方，你已经会了，不用再花时间。

## 4. 八个学习单元（把 A0~A7 变成学习单元）

每个单元 = 一个动手任务 + 它自带的知识点 + 一份可验收的证据 + 一句脱稿自测。

---

### 单元 1 · A0 环境与基线

**动手**：用 `.venv-react` 起后端，用 curl 打一次 `/chat/stream`，把原始字节存成文件。

```bash
# 启动（Windows / Git Bash）
./.venv-react/Scripts/uvicorn.exe service.api:app --port 8000

# 另开一个终端：发出真实请求，保留原始字节
curl -N -X POST http://127.0.0.1:8000/chat/stream \
  -H "Content-Type: application/json" \
  -d '{"question":"招标方式有哪些？","thread_id":"demo-001","deadline_s":60}' \
  | tee "$TEMP/raw_sse.txt"
```

**顺手做一件总纲没提但很值钱的事**：回答之前先写下预测——"我猜会先来 meta，再来若干个 stage，然后 token，最后 final"。然后跟 `raw_sse.txt` 对比。**这就是你第一次真正看见 chunk。**

**知识点**：浏览器 / React / FastAPI / AgentGraph / MySQL·Milvus·LLM 五层分工；A 与 B 的范围区别。

**证据**：一份 `raw_sse.txt`，能指着它说出每条 frame 是谁发的、为什么发。

**脱稿自测**：不看文档，画出网页请求链路，标出哪一层持有密钥。

---

### 单元 2 · A1 冻结前后端契约

**动手**：为 `ChatRequest`、`StreamEvent` 写 TypeScript 类型；给每种事件存一份脱敏样例。

**知识点**：HTTP POST 与 JSON 请求体；SSE frame 结构；TypeScript 可区分联合；`request_id` 与 `thread_id` 的区别。

**证据**：一份事件样例集 —— 11 种事件各一条真实 JSON。这份文件后面写 reducer 时天天要用。

**脱稿自测**：`thread_id` 和 `request_id` 分别回答什么问题？为什么不能合并成一个？

---

### 单元 3 · A2 静态界面骨架

**动手**：建独立前端目录，用假数据把聊天区、阶段区、引用区、输入区搭出来。

**知识点**：组件 / props / state 的区别；为什么选 React + TS + Vite；React 列表 key。

**证据**：不连后端，只靠假数据就能演示所有组件状态（含空态、错误态）。

**脱稿自测**：引用卡片为什么不该自己发请求，而应该接收已解析好的 props？

---

### 单元 4 · A3 接入真实流式接口

**动手**：`fetch` 发 POST，增量读 `response.body`，reducer 归约，`AbortController` 停止。

**这个单元是整个项目知识密度最高的地方**，也是唯一一个我建议你**先看实验结果再看文档**的单元：

- 本仓库 [`learning_lab/01_chunk_not_frame.py`](../../learning_lab/01_chunk_not_frame.py) —— 证明 chunk ≠ frame
- 本仓库 [`learning_lab/02_buffer_bytes_not_str.py`](../../learning_lab/02_buffer_bytes_not_str.py) —— 证明必须缓冲字节而非字符串

先跑这两个脚本，**再**回头看总纲 §5 第 10 步和 §6.3。

**知识点**：`fetch + ReadableStream` 为什么替代原生 `EventSource`；chunk 与 frame 的区别；UTF-8 边界；CORS；`AbortController`；为什么流式事件适合 reducer。

**证据**：连续三轮请求不串流；点停止后下一轮正常；控制台能看到一次真实的 CORS 报错并被修掉。

**脱稿自测**：一个 chunk 里能不能有多条 frame？一条 frame 能不能跨多个 chunk？各举一个你就遇到过的例子。

---

### 单元 5 · A4 实现领域结果组件

**动手**：`citations` → 引用卡片；`table` → 结构化表格；`stage/retrieval` → 进度文案；Markdown 安全渲染。

**知识点**：为什么引用和表格走结构化事件而非文本解析；为什么不展示原始思维链；模型输出属于不可信输入。

**证据**：知识问答、价格查询、一般对话各一条受控样例。

**脱稿自测**：为什么不能从回答正文里正则提引用？

---

### 单元 6 · A5 接入飞书应用机器人

**动手**：创建企业自建应用 → 启用机器人 → 申请最小权限 → 订阅消息事件 → 写适配层。

**知识点**：自定义机器人 vs 应用机器人；权限 / 事件订阅 / 可用范围三者的区别；幂等去重；防自回复循环；会话映射。

**证据**：同一飞书会话连续两轮保持上下文；故意重复投递同一事件，只触发一次模型调用。

**脱稿自测**：为什么"配上事件订阅"不等于"能收到消息"？为什么"能发消息"也不等于"能问答"？

---

### 单元 7 · A6 异常与恢复验证

**动手**：把 A 阶段方案 §A6 列的九种失败**逐个真实制造一遍**。

**知识点**：三种终态的语义差异；半截流不算成功；`request_id` 隔离迟到事件。

**证据**：一张九行表，每行 = 故障注入方式 + 页面实际表现 + 是否符合预期。

**脱稿自测**：业务拒答为什么可以是 `final` 而不是 `error`？

---

### 单元 8 · A7 作品集包装与演练

**动手**：README 启动步骤、架构图、3~5 分钟演示脚本、三条稳定问题、"已实现 / 已验证 / 未完成"清单。

**知识点**：如何诚实表述已实现与未实现；如何把话题拉回 Agent 集成和验证。

**证据**：全新终端按 README 能启动；不看代码能讲完一次请求的数据流。

**脱稿自测**：总纲 §17 Q25 那段话，不用稿子说一遍。

## 6. 五个最容易背错的点（已对照代码核实）

这五条是总纲写了、但**只读文档会理解偏**的地方。它们正好都在你要动手的路径上。

### ① `deadline_s` 只能缩短，不能延长

总纲 §6.1 说 `deadline_s` 是"本轮总时限"，容易读成"我传多少就是多少"。
实际 `agent/graph.py:355` 是：

```python
limit = min(deadline_s or self._settings.agent_request_timeout_s,
            self._settings.agent_request_timeout_s) if controlled else deadline_s
```

也就是**受控路径下取 `deadline_s` 与配置超时的较小值**。前端传 100 秒而配置是 60 秒，实际就是 60 秒。
另外 `service/schemas.py:10` 还有一层 `gt=0, le=120` 的请求级上限。
面试点：超时是**服务端参数被前端收紧**，不是前端指挥服务端。

### ② 业务拒答是 `final`，不是 `error`

直觉会把"没答上来"归到失败。但总纲 §8.3 的语义是：**证据不足后按规则拒答，业务流程完整结束了**，所以是 `final`。

`service/api.py:39` 把 `FINAL / ERROR / CANCELLED` 并列为终态，三者都结束本轮，但含义完全不同。
面试点：终态回答的是"这一轮结束了没"，不是"这一轮成功了没"。

### ③ 必须缓冲**字节**，不能缓冲**字符串**

总纲 §5 第 10 步只写了"处理 UTF-8 边界"，没说为什么。
真原因是：一个汉字在 UTF-8 里占 3 字节，TCP 可以从中间切断。先 decode 再拼字符串会直接抛异常 —— 页面在**中文回答上随机崩溃**，而且极难复现。

`protocol.py:110` 的 `parse_sse_stream` 用 `bytearray` 缓冲、扫到 `\n\n` 才 decode，正是为了这个。
前端对应：`TextDecoder` 必须开 `{ stream: true }`。
→ 跑 [`learning_lab/02_buffer_bytes_not_str.py`](../../learning_lab/02_buffer_bytes_not_str.py) 亲眼看这个异常。

### ④ CORS 不是认证，而且当前后端**压根没配**

`CORS` 是浏览器的访问控制；配了它，非浏览器客户端（curl / Postman）照样直接打你的接口，因为它根本不执行同源策略。
**这是当前项目的一个真实缺口**：全项目 grep 不到 `CORSMiddleware` / `allow_origins`。
所以前端一旦跑起来，你**一定会**撞到它 —— 这正是它最好的学习时机。

### ⑤ 飞书"能推送" ≠ "能问答"

自定义机器人只能通过 Webhook 往群里推；能接收消息事件、并调用回复接口的，是**应用机器人**。
写作品集时必须分清：只做了 Webhook 推送还算不上"飞书里能向 Agent 提问"。

## 8. 节奏建议

不按"每天几小时"排，按**会话**排 —— 每个单元一次专注 + 一次脱稿复述。

| 批次 | 单元 | 说明 |
| --- | --- | --- |
| 第 1 次 | 单元 1 | 纯观察，不写代码。产出一份 `raw_sse.txt` 和一张手画的数据流 |
| 第 2~3 次 | 单元 2 + 3 | 类型与骨架。可以用假数据，不碰后端 |
| 第 4~5 次 | 单元 4 | **最重的一次**，留足时间，先跑 learning_lab |
| 第 6 次 | 单元 5 | 领域组件 |
| 第 7~8 次 | 单元 6 | 飞书。**先确认你有没有建应用的权限**，没有就走降级方案 |
| 第 9 次 | 单元 7 | 故障注入，最枯燥但面试最加分 |
| 第 10 次 | 单元 8 | 包装与演练 |

**卡住超过 40 分钟就停下来问我。** 按 SOUL 的精神，硬扛不是美德，把问题描述清楚再问才省时间。

1. 第一条 frame 是什么类型？为什么是它先来？

**这三问的答案，就是总纲 §5 和 §16.1 前两条知识点的全部内容。**
