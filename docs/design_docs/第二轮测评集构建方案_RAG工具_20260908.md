## 2. 题从哪里来

**可以重新出题，也可以复用一轮 2000 题题集中的问题。** 无论来源如何，都要按当前新 chunk 重新核对答案、ID 和题型。现有题集中的 53 道旧题来自一轮的 200 题子集，本次新增多跳题直接从当前 chunk 编写。

当前新 chunk 位于 `D:/DEMO/zhaotoubiao_demo_copy/DATA/repaired_knowledge/`：

- `book1/documents.jsonl`：316 块。
- `book2/documents.jsonl`：161 块。
- `book3/documents.jsonl`：443 块。

合计 920 块。新旧系统各用自己的 chunk，**不要求切分相同**。

**二轮固定为 130 道单跳（65%）、70 道多跳（35%）。** 单跳由 1 个新 chunk 支持，多跳由 2 个互补的新 chunk 支持。这个“多跳”不等于需要多次调用工具；按新切分重新核对，不能只改标签或随意增加一个来源 ID。

能用的旧问题原样保留；缺少背景的补全；资料范围外或不合适的题才替换。需要补题时，从现有 chunk 中提取有明确答案的常规问题，不额外增加复杂情境、计算或追问要求。**最终新题集固定 200 题，总数不再增加；尽量与旧题保持问题一致。**

本次结果：45 题原样复用旧问题，8 题补全或改写旧问题，147 题从新 chunk 补充。补题主要利用《1200问》已有的完整问答，改成清楚、独立的问题，答案保留原文依据。用户已审核的旧第 11、20、25 题放在新题集第 1—3 行，问题和答案均未改动。

本次将原 198 道单跳中的 68 道改造为直接汇总或对照题，保留原 2 道多跳及其余 130 道单跳，达到 130/70 配比。共涉及 164 个不同的新 chunk。配比一致，不代表两轮实际难度已经测得相同。

## 3. 每道题记录什么

沿用旧题集的五个字段，不另加一套旧 chunk 标注。字段可以全部保留，但内容不能全部照抄：

| 字段 | 新题集如何填写 |
|---|---|
| `question`（问题） | 适用且表述完整的旧问题原样保留 |
| `reference`（参考答案） | 核对新 chunk 后，正确且完整的保留；有错或缺项的修正 |
| `ground_truth_chunk_ids`（目标块 ID 列表） | 重新填写新 chunk 的 `metadata.chunk_uid`，不放旧 ID |
| `ground_truth_text`（目标块正文列表） | 重新提取对应新 chunk 的完整正文，与 ID 列表逐项对应 |
| `query_type`（题型） | 保留字段和 `single_hop`、`multi_hop` 标签；按新切分下回答所需的单块或跨块情况重新核对，不代表 ReAct 推理能力 |

旧 ID 是整数，新 `chunk_uid` 是 `ck-...` 字符串。字段仍是列表，但旧评分脚本若把 ID 强制转换为整数，需要适配；不能仅凭字段名相同，就认定脚本可以直接运行。

同一答案如果也完整出现在其他 chunk 中，应允许它作为正确来源。不能只有标准答案，却没有对应 chunk。

## 4. 看哪些结果

| 要知道什么 | 检查什么 |
|---|---|
| 找到了吗 | 返回结果是否包含正确的目标 chunk |
| 找全了吗 | 回答所需的内容是否全部找齐 |
| 排得好吗 | 正确 chunk 是否排在前面，例如前 5 条 |
| 哪里丢了 | 是没有召回，还是被阈值过滤掉了 |
| 代价如何 | 检索耗时、返回文本量；调用费用如有则记录 |

以上评价检索工具，不要求工具自己推理或追问。如果继续测回答质量，再接固定的回答模型，用 Ragas 看“是否有依据、是否答在点上、是否正确”；回答成绩与检索成绩分开。
