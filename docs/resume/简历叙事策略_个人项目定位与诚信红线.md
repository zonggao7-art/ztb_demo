# 简历叙事策略：个人项目定位与诚信红线

> 针对两个问题：
> ① 两个项目都是个人项目、无企业生产经历，简历会不会很水？
> ② 能否把 RAG 项目包装成"企业级知识库 + 我非核心职责"，以此防止深度拷问？
>
> **结论：① 不水，不用担心。② 不能做，这一招会反噬。**

---

## 一、"两个个人项目会不会很水"——不水，但你有一个真问题

### 1.1 面试官判断"水不水"从来不看这个标签

判断标准只有三条：

| 判断标准 | 你的情况 | 评价 |
|---|---|---|
| 有没有**真实、可复现**的数据？ | 200 题检索对照，宏平均召回 68.00% → 94.25%；280 题 × 3 轮 Agent 评测；920 个法规片段；58,458 条结构化数据 | ✅ 远超平均 |
| 有没有**主动承认失败与边界**？ | 材料里写明"当次系统正式验收未通过""无生产 QPS 结论""本机演示，无生产鉴权" | ✅ 极少有人做到 |
| 能不能讲清**技术取舍的理由**？ | 工具合同设计、三种"没查到"的区分、为什么阶段性下线产品线 | ✅ 有 |

**反面参照**：大量简历上写着"负责某公司 XX 系统开发"的项目，一问"数据量多少""怎么评测的""遇到什么问题"，当场就空。**那才叫水。**"个人项目"这个标签本身从来不是减分项，"没有数据、没有边界、没有取舍"才是。

### 1.2 你唯一的真问题：两个项目撞型，且质量倒挂

| 维度 | 主项目（招投标） | RAG 项目 |
|---|---|---|
| Embedding | BGE-M3，1024 维 | bge-small，512 维，跑 CPU |
| 精排 | BGE-reranker-v2-m3 | 无 |
| 引用溯源 | 片段级引用 + 校验 | 不返回来源 |
| 评测 | 200 题 + 280×3 轮 | 零评测 |
| 工程化 | Docker / pytest / PR 流程 / 服务化 | 命令行脚本 |

两个 RAG 项目并排，面试官会得出**"这个人只会在同一件事上重复练习"**的结论。这才是真正要解决的问题——而且它跟"是不是个人项目"毫无关系。

### 1.3 解法：不换角色，换标题

把副项目标题从《半导体领域 RAG 知识库》改为：

```
《RAG 自我纠正范式对比验证》
```

标题一改，三件事同时发生：
1. "为什么做两个知识库"的撞型质疑消失——一个做产品，一个做研究；
2. 项目性质从"重复练习"变成"有目的地探索"；
3. 面试官的提问会自动停在"你的结论是什么"这个层级，因为对比研究项目的天然终点就是结论。

## 二、"包装成企业级 + 非核心职责"——不建议，这一招反噬

### 2.1 "非核心职责"不是保护伞，是把能答的题换成不能答的题

它的逻辑是矛盾的：**既然你不是核心，这个项目凭什么写进简历？** 面试官一定会顺着这个矛盾往下问，而且问的都是你最答不上来的方向：

| 因为"非核心"而必然被问 | 你的处境 |
|---|---|
| 团队多少人？你负责哪几个模块？ | 技术细节你至少看过代码，团队构成你是零 |
| 谁给你 review 代码？怎么协作的？ | 编不圆 |
| 这个知识库服务多少人？哪年上线的？ | 编不圆，且一查就露 |
| 公司叫什么？什么规模？ | **三个问题就能套出虚实** |

**本质问题**：降低角色不会减少提问，只会把提问从"技术层"转移到"履历层"。而你手里唯一真实的东西就是技术——技术细节你能答，虚构的团队经历你一个字都答不了。**这是净亏。**

### 2.2 这是简历里最容易验证的那类谎言，代价是整份简历

一旦被识别出履历虚构，后果不是"这个项目减分"，而是**整份简历所有内容一起打折**——包括你主项目那些辛苦攒出来的真实数据（68%→94.25%、280×3 轮、58,458 条数据）。

用两个月的真实工作，去换一个虚构项目的光环，这笔账怎么算都亏。

### 2.3 而且它和你自己已经定下的纪律冲突

你的《面试项目说明》里已经写着：

> "项目选择的应用场景，尚未测量真实用户检索时间或业务效率。**面试中不应扩写成已经服务某公司、支撑某业务规模。**"
> "200 请求、并发上限 16 的故障隔离属于受控测试，**不能写成生产并发能力**。"

你已经知道正确答案了。为副项目破例，要付的代价是把这套纪律的可信度一起赔进去。

## 三、防止深挖的正确做法：不降低角色，提高框架层级

| 错误做法 | 正确做法 |
|---|---|
| 降低角色（"我只是参与者"） | **提高自述层级**（让提问停在设计思想层） |
| 效果：话题转向履历，更危险 | 效果：话题停在概念层，自动收敛 |

### 三招具体动作

**第一招：主动交底边界（最强防御）**

> "这个项目只跑通流程，没做生产化改造，也没做定量评测——评测方法论我是放在主项目里实践的。"

这一句说完，**所有生产相关的追问全部失效**（没有用户、没有并发、没有 SLA、没有成本优化），你不用再编任何东西。

**第二招：用"结论"收尾**

学习/验证类项目的提问深度上限就是"你的结论是什么"。给出结论，对话自然结束：

> "结论是纠错闭环能把单次问答的 LLM 调用从 2 次推到 8 次左右，延迟翻倍。所以我在主项目里没有采用它。"

**第三招：把"个人项目"讲成优势而不是遗憾**

个人项目能做企业项目做不了的事：自由试错、完整对比多种范式、把评测报告写完整。企业项目往往只有一次机会，方向错了也得上线。

> 你要证明的从来不是"我在企业里干过"，而是"**我有独立判断和验证的能力**"。
> 前者靠经历，后者靠证据——你手里的证据比大多数有企业经历的人更硬。

## 四、如果目标岗位确实需要企业背景怎么办

**答案是去挣，不是去编。** 按性价比排序：

1. **实习 / 外包 / 兼职项目** —— 哪怕只有两个月，一个真实生产环境就能补齐这块短板；
2. **开源贡献** —— 有 PR 记录、有 review 过程、可被验证，且过程本身就是团队协作的证明；
3. **接一个真实的小需求** —— 给身边人做个工具并真的被使用，就能诚实地写"服务 N 名用户"。

一段真实的生产经历，比包装十个项目都有效。

## 六、一句话总结

> **"个人项目"不是缺陷，"没有数据、没有边界、没有取舍"才是。**
> 你的三个都不缺，所以不水。
> 真正要修的只有一件事：**让两个项目各占一个生态位**——主项目做产品落地，副项目做范式研究。
> 至于伪装企业背景，省下的那点提问风险，赔不起整份简历的可信度。
