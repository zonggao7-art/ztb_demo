## 一、先把项目、价值与个人贡献讲清楚（Q001—Q010）

### Q001. 请先介绍一下这个项目：你为什么做它，用户能用它完成什么？

**参考答案：** 我用两个月独立开发了一个招投标智能助手，定位是供应商信息核查和场景化法规咨询。用户可以查询企业工商、处罚、中标历史，再沿项目编号了解中标详情，也可以描述业务场景获取带来源的法规解释。我把结构化数据库和法规知识库封装成工具，由主 Agent 组织调用，做了网页和飞书入口。目前它是可以直接体验的个人项目，还没有真实业务用户，主要通过自建评测和链路联调验证效果。

### Q002. 企业信息和法规都能在网站上查，你这个项目增加了什么价值？

**参考答案：** 我的价值假设是减少围绕同一业务问题切换信息入口的成本。例如核查一家供应商时，用户关注的往往不止工商信息，还包括处罚和历史中标项目；法规问题也可能是一段场景描述，而不是明确的法条名称。我尝试把这些信息组织成连续的查询过程，并保留事实和引用依据。但我不会声称其他网站都做不到，也没有真实用户数据证明节省了多少时间，这部分价值还需要实际任务验证。

### Q007. 这个项目里，你做过代价最大的一次取舍是什么？

**参考答案：** 是收敛开放式查询范围。最初希望支持任意排名、推荐和行情问题，测试却暴露了条件映射、字段遗漏，以及能力范围超出数据基础的问题。我后来固定核心业务的输入、取数和输出规则，超出范围就明确引导。这降低了灵活性，但让查询有了稳定的验证对象。之后加入 Agent，我没有重新开放任意 SQL，而是在可靠工具上允许逐步组合调用，把工具能力和编排灵活性分开处理。
