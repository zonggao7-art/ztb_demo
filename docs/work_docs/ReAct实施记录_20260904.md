## 1. 当前状态

### 2026-09-06：主体名称放行，恢复旧版引导

本次只修默认 hybrid 入口的两项行为，没有调整 ReAct 计划、循环次数或并行策略，也没有引入 Text2SQL、新 SQL 工具或第二层意图模型。

- 目的在既定六类 SQL 问题内，就按用户提供的主体名称查询。模型不审核主体真实性、全称或后缀；执行层也不再要求名称符合“公司”等后缀。
- 六类为：工商信息、行业/经营范围、处罚/不良记录、企业中标历史、指定项目编号的中标情况、采购人采购/发包历史。范围外的问题走固定引导；仅给名称但未说明目的，则询问查询事项。通用业务搜索不作为绕过这六类目的的入口。
- SQL 仍是固定表、固定字段、参数化精确查询，保留只读、超时与条数限制；底层额外检查空值和参数长度。没有降低数据库安全边界。
- 查询成功但无记录说明“暂未收录匹配记录”；记录字段为 NULL/空文本显示“未收录该字段”；查询失败说明服务未成功返回，不冒充查无记录。
- 旧 `general_chat` 的欢迎语提取为共享常量，文字保持原样。hybrid 的问候与不支持请求均复用它；`unsupported` 状态和 `fallback` 分支标签仍保留，不因展示欢迎语而假装业务已完成。

验证结果：

- 新增 24 项离线测试，覆盖真实工具包装、SQL 参数绑定、超时故障、空结果、字段空值、ReAct 名称放行和旧引导一致性。全部测试 **583 通过、1 跳过**。
- 15 个真实模型分流用例符合上述范围，包括六类查询、商店/学校名称、双主体、地址/单独字段查询与闲聊。该组只测试路由，未执行业务工具。
- 同一会话连续 9 次真实流式请求通过：“你好”“天气怎么样”“你能干什么”；张三公司中标历史；张三商店中标历史；张三商店和李四小铺中标历史；商店位置；仅给商店名称；已收录企业工商信息。工具次数分别为 0、0、0、1、1、2、0、0、1；五次真实 SQL 查询成功完成，空结果和有记录的结果均正常，流式正文与最终正文一致。

## 3. 一次请求现在怎样运行

新链路在 `agent/execution/` 下，实际顺序如下：

```text
用户问题
  ↓
service.py：检查是否命中 hybrid 灰度
  ↓
router.py：让模型提出执行方案
  ↓
policy.py：程序审核方案
  ↓
executor.py：执行 static 或受控 ReAct
  ↓
evidence.py：登记可追溯证据
  ↓
output.py：核对答案并渲染最终结果
```

各文件职责：

| 文件 | 通俗说明 |
|---|---|
| `agent/execution/contracts.py` | 定义模型必须填写的固定表单 |
| `agent/execution/router.py` | 判断任务类型并提出任务清单 |
| `agent/execution/policy.py` | 检查这个清单是否允许执行 |
| `agent/execution/context.py` | 管理超时、次数、取消、日志和本次请求上下文 |
| `agent/execution/executor.py` | 调用官方 Agent 或固定流程执行任务 |
| `agent/execution/evidence.py` | 保存本次请求可引用的真实证据 |
| `agent/execution/output.py` | 阻止未经核验的模型文字直接发布 |
| `agent/execution/service.py` | 串起上述步骤，并处理灰度和安全回退 |

旧 Router 和旧 StateGraph 没有删除，保留为显式回滚通道。`--agent-mode` 是兼容入口，也走受约束链路；普通使用不需要它。

## 4. Router 已经受到哪些限制

Router 只负责提出建议，没有最终决定权。它必须返回固定结构，内容包括：

- 选择 `static`、`react`、`clarify` 或 `unsupported`；
- 最多列出 6 个任务；
- 标明任务之间的依赖；
- 说明每个参数来自当前问题、近期对话还是前序工具结果；
- 只能建议白名单中的工具；
- 使用有限的原因码和缺失字段，不输出任意解释来绕过规则。

程序会再次检查这些内容。格式错误最多修正一次，仍不合格就停止。系统不依靠“同时”“并且”等关键词启动 ReAct。

## 5. 工具调用已经受到哪些限制

工具注册中心目前包含八个工具：

```text
search_public_kb
knowledge_qa
query_company_registration
query_company_business_scope
query_company_penalty
query_project_award
query_company_award_history
search_business_data
```

其中主 Agent 和 hybrid 执行器只获得六个业务工具；`search_public_kb` 与 `search_business_data` 保留注册但不授权。

共同规则：

- 单个模型回复最多调用一个业务工具；
- 单请求工具并发数为 1；
- 批量工具调用会在真正执行前整体拒绝；
- 参数必须能追溯到用户输入或已核验的前序结果；
- 完全相同的调用在本次请求内可复用缓存；
- 非法参数最多允许修正一次；
- 每次调用都有明确的工具调用 ID、超时和审计记录。

## 6. SQL 适配器做了什么

新链路使用 `agent/tools/strict_sql.py`。它只服务于受约束 ReAct，不改变旧价格查询分支的行为。

主要边界如下：

- 所有查询只读、参数化，并带明确的结果数量上限；
- 精确查询优先，不允许模型生成任意 SQL；
- 查询在只读事务中运行，并使用有界连接池；
- 超时线程没有真正结束前，连接和并发名额不会被提前释放；
- 进入最终答案阶段后，后台工具也不能借机延长自己的截止时间。

各类查询的当前能力：

- **企业工商信息**：只允许企业名称作为检索条件，不返回经营范围。
- **企业经营范围**：只允许企业名称作为检索条件，只返回名称与经营范围。
- **企业处罚**：要求企业全称；当前不开放处罚日期筛选。
- **项目中标情况**：只开放项目编号精确查询，不开放项目名称或采购人查询。
- **企业中标历史**：只开放中标供应商名称精确查询，不开放采购人查询。
- **业务搜索**：只返回有限候选；优先 FULLTEXT，必要时使用有界 LIKE。搜索不到不能证明现实中没有该记录。

本次实施没有修改业务数据、数据库索引或 Milvus 集合。生产环境仍需配置权限受限的只读数据库账号。

## 7. 答案为什么不能由模型直接发布

工具结果先进入本次请求的证据账本。模型只能提交规定类型的答案草案，例如“引用某条记录的指定字段”或“引用某段法规原文”。`output.py` 再用真实数据生成最终答案。

这样可以阻止以下问题：

- 模型补造公司、项目、日期、金额或法规内容；
- 把检索到的少量结果说成完整全集；
- 把“没有查到”说成“绝对不存在”或“没有风险”；
- 引用模型没有真正看到的原始内容；
- 某个子任务失败后，仍把整项任务标成完成。

`complete` 只表示经过批准的任务都已完成且证据有效，不表示 Router 绝不会漏掉用户意图，也不表示系统已作出法律判断。

## 8. 已知限制

下面这些不是隐藏问题，而是当前版本有意保留的边界：

1. 输入上限按 UTF-8 字节保守计算，不是针对具体模型校准后的精确 token 数。
2. `static` 在 hybrid 模式下也经过受控适配器，不等于直接复用旧节点的自由文本答案。
3. 普通闲聊只支持问候和能力说明，不扩展为开放式聊天机器人。
4. 法规引用可以证明“这段文字来自哪里”，但不能自动证明它一定适用于当前案件。
5. 结构化输出只能保证格式，不保证模型永远正确理解语义，因此必须做人工评测。
6. 当前会话锁主要覆盖单进程；多实例部署还需要分布式锁和可信身份绑定。
7. 当前不承诺服务崩溃后从 ReAct 中间步骤继续恢复。
8. 文档问答、文件上传、多模态、任意 SQL、写操作和多智能体协作仍不开放。

## 13. 如何试用与如何回滚

建议直接在项目目录运行下面的命令：

```powershell
.\.venv-react\Scripts\python -B -m agent --interactive --stream
```

未被已有配置覆盖时，这条命令默认进入新架构。输入 `clear` 后生成新的会话 ID，仍进入新架构。界面会显示实际模式、分流结果、任务清单和工具状态。

若要验证旧流程，增加 `--execution-mode legacy`。若当前环境限制了新架构准入，可以增加 `--execution-mode hybrid`，只为当前 CLI 会话明确选择新架构，不修改 `.env`。新入口不需要额外打开 `AGENT_TOOLS_ENABLED`。

若部署环境尚未通过生产验收，应显式限制准入，而不是直接沿用 100% 默认值。例如内部审阅时：

1. 把执行模式设为 `hybrid`；
2. 只把测试用 `thread_id` 加入 `AGENT_REACT_THREAD_ALLOWLIST`；
3. 保持总体灰度为 0，避免其他会话进入新链路；
4. 如使用 `--agent-mode`，还需显式设置 `AGENT_TOOLS_ENABLED=true`。

同一 `thread_id` 会稳定落在同一灰度桶。未命中灰度的会话继续走旧图；旧图不具备新链路的证据发布门槛，不能用它冒充 ReAct 完成复合业务验收。

回滚方式：把 `AGENT_EXECUTION_MODE` 改回 `legacy`，然后重新加载 `AgentGraph` 或重启服务。配置在实例初始化时读取，不是热更新。

因为本次没有数据库迁移、数据写入或知识库改造，所以回滚不需要恢复 MySQL 数据或 Milvus 集合。
