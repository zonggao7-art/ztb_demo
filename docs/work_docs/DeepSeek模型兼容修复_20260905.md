# DeepSeek 模型兼容修复

## 故障与范围

用户将模型切换为 `deepseek-v4-flash-vision-exp`，使用官方 `https://api.deepseek.com` 接口后，legacy Router 出现 HTTP 400：`Thinking mode does not support this tool_choice`。

这是模型请求参数兼容问题，不是知识库无答案，也不是此前的异步连接池问题。首次结构化请求的具体 400 内容未在用户日志中展开；后续强制工具选择与思考模式冲突则有明确日志。

DeepSeek 官方文档提供 `extra_body={"thinking": {"type": "disabled"}}` 开关；工具思考模式还要求回传历史 `reasoning_content`。本次保守策略为结构化/工具请求使用非思考模式，普通正文生成保持原配置，避免扩大到未经验证的工具思考链路。

参考：[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。

## 实现

### 统一模型适配

在 `public_kb/llm_factory.py` 的既有 `BudgetedChatOpenAI` 中适配：

- 仅按 endpoint 的准确 hostname `api.deepseek.com` 识别，不依赖模型名模糊匹配。兼容官方根路径及 `/v1`、`/beta` 等路径；不把第三方代理/OpenRouter 当作 DeepSeek 官方接口。
- 默认结构化输出及显式 `json_schema` 请求转换为 `function_calling`，仍由 Pydantic 校验结果，不解析未约束自由文本。
- 显式 `json_mode` 仍保留 JSON Object 模式。
- 结构化输出及 `bind_tools` 在该次调用中禁用 thinking；保留原有 `tool_choice`，不把 `required` 偷换为 `auto`。
- 保留其他 `extra_body` 字段，使用复制/绑定而非修改共享实例，普通 RAG 正文生成不被全局禁用思考。
- 保留原 `_for_run()`、预算计数、重试限制及提示词预算检查。ReAct 的路由、工具选择和 `AnswerCandidate` 因共用模型适配而一并受益；没有绕过 `execution/output.py`。

### 路由与错误提示

- `agent/graph.py` 创建 legacy 路由模型时显式设置 `temperature=0`。
- `agent/router.py` 在调用失败时返回安全、明确的“模型路由服务调用失败”提示，通过原 fallback 节点显示，不再让用户误以为问题不清楚/超纲。
- 失败时清除缓存的工具回退标志，让下一轮重新尝试结构化路径；成功的工具回退仍可复用。
- 错误提示与路由错误日志不带原始供应商响应正文。

未修改 `.env`、依赖或模型名称；未修改 Milvus/MySQL 数据及服务；没有改变 hybrid 灰度和发布边界。

## 验证

使用已有独立环境 `.venv-react`，未安装或升级全局依赖。

### 离线

- 新增 `test/test_deepseek_compat.py`：16 项用例，使用真实 OpenAI SDK 和 HTTPX MockTransport 检查实际请求体。
- 覆盖同步/异步结构化调用、默认/function_calling/json_schema、显式 json_mode、强制/自动/指定工具、非 DeepSeek 不受影响、共享配置不变、非法路由枚举拒绝，以及路由失败后的恢复。
- 扩展 `test/test_react_runtime.py`：DeepSeek 请求参数下完整执行 Router → 官方 Agent 循环 → 模拟只读工具 → AnswerCandidate → 校验发布，仍为 3 次模型调用、1 次工具执行，原始模型配置不变。
- 完整回归：**451 passed, 1 skipped，60.04 秒**。跳过的是默认关闭的 live RAG 集成测试。
- 最后调整 MockTransport 测试的实际 endpoint 后，再运行模型兼容 + ReAct runtime：**26 passed，6.64 秒**。

## 启动

退出旧进程，保留现有 DeepSeek `.env` 配置，在项目根目录执行：

```powershell
.\.venv-react\Scripts\python.exe -m agent --interactive
.\.venv-react\Scripts\python.exe -m agent --interactive --stream --timeout 60
```

第一条是普通交互，第二条是流式交互，按需选择一条。直接使用已验证解释器，不需要依赖 `conda activate .conda` 是否成功。

代理平台、其他实验型号或未来参数协议变更需要单独验证；本补丁不会对所有 OpenAI-compatible 服务发送 DeepSeek 专有参数。真实服务不可用时仍会返回明确错误，不进行无限重试。
