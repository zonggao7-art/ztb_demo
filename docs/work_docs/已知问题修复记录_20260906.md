# 已知问题修复记录

本轮只修复已经明确的问题，不调整架构，也没有启动或修改数据库服务。

## 改了什么

1. **工商查询只允许公司全称。** 工具参数、权限校验、SQL 执行层均不再允许城市、行业、状态或日期等额外筛选。城市和行业仍然可以出现在查询结果中。`task_id`、`top_k` 保留为任务追踪和数量控制参数，不是业务筛选条件。
2. **路由错误不再全部混为一谈。** 空任务清单显示 `tasks_required`，重复绑定显示 `duplicate_binding`，日志和 CLI 显示安全的错误位置；网络与程序异常分别报告，不再要求模型“纠正网络错误”。不输出原始异常或未经检查的字段名、字段值。
3. **一次纠错给出具体提示。** 明确告诉模型问候也需要一个 `general_chat` 任务，多家公司必须分成不同任务。仍只允许一次纠错，没有替模型自动补任务，也没有放宽校验规则。
4. **修复执行器导入位置。** `policy.py` 的语法错误已由用户修好，本轮未重复处理。`executor.py` 存在同类问题，只把 `from __future__` 移到合法位置，保留学习说明全文。

## 没有改什么

- 没有新增“两家公司必须走固定流程”的规则；同一个工具仍可用于多个任务。
- 没有决定删除哪个 RAG 工具，也没有增加动态规划或检索质量判断。
- 没有修改 `.env`、模型身份、调用预算、数据库内容、索引或 Milvus 集合。
