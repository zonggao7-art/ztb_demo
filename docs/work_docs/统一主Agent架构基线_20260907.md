# 统一主 Agent 架构基线

> 日期：2026-09-07  
> 状态：默认入口已切换，旧 hybrid / legacy 保留为显式回滚通道  
> 目标：先用最少变量证明系统基本链路可运行，再讨论是否增加推断能力

## 1. 本次变更解决什么问题

此前默认链路是：

```text
用户问题 → Router 生成模式、任务、参数和依赖 → static 或 ReAct → 确定性发布
```

Router 已经完成了任务理解和计划，ReAct 只能在批准清单内执行。模型虽然处在 Agent 循环中，却没有根据工具结果重新决定任务路径的空间。

现在默认链路是：

```text
用户本轮问题
    ↓
统一主 Agent：申请一个业务工具，或提交 FinishAction
    ↓
程序逐次检查工具、参数来源、预算和结果范围
    ↓
经核验的工具结果返回主 Agent
    ↓
主 Agent 决定下一次工具或结束
    ↓
程序按证据确定性发布
```

简单任务和复杂任务不再由顶层分类器预先决定。一次工具调用后结束就是简单路径；根据结果继续调用第二个工具就是多步路径。

## 2. 当前模型权限

模型可以：

- 理解本轮问题；
- 从六个已审核的只读业务工具中选择下一步；
- 使用用户本轮原文作为参数；
- 使用前一步已核验、且对模型可见的记录字段作为后一步参数；
- 根据工具成功、空结果或失败，选择继续、澄清、不支持、部分完成或完成。

模型当前不能：

- 读取历史轮次来补参数；
- 同时申请多个业务工具；
- 使用模糊业务搜索或原始法规片段检索；
- 自行编写 SQL、访问任意表、写数据、联网或触发外部影响；
- 自由撰写最终业务结论；
- 把工具失败解释为没有记录；
- 根据多工具结果发布跨来源推断。

## 3. 初始工具面

| `knowledge_qa` | 法规知识问答 | 复用工具内部已完成引用校验的完整答案 |

## 4. 程序仍然掌握的边界

每次工具申请都会单独经过程序授权：

1. 工具必须属于六项业务白名单并且当前已启用；
2. 参数必须通过工具 schema，且不能携带旧 Router 的 `task_id`；
3. 查询字段必须属于该工具的最小字段集；
4. 文本参数必须逐字来自当前问题，或来自前一步已核验的可见记录；
5. SQL 工具只进入固定表、固定字段、参数化、只读的精确查询适配器；
6. 每次模型回复最多一个动作，模型调用数、工具调用数、超时和输入长度均有上限；
7. SQL 返回记录必须再次匹配查询主体；RAG 返回必须再次通过引用结构校验；
8. 最终正文只能来自已核验的数据库字段、完整 RAG 答案或固定限制说明。

结束动作采用固定结构：

```text
FinishAction.status = complete | clarify | unsupported | partial
FinishAction.missing_fields = 标准缺失字段列表
```

`complete` 是模型的停止决定，不是程序对“用户全部语义均已覆盖”的证明。程序会在有工具失败、验证失败或缺失条件时把最终状态收紧为 `partial`。任务覆盖是否稳定由独立测评衡量，避免重新引入一个语义 Router 来审核另一个模型。

## 5. 最小变量测评

### 5.1 工具契约与程序边界

离线测试覆盖：工具白名单、参数来源、虚构参数拦截、串行调用、批量动作整批拒绝、结果范围回验、确定性发布、默认入口和回滚入口。

六工具拆分相关的离线回归结果：**173 项通过，1 项跳过**。全量套件最终一次运行结果为 **591 项通过、4 项跳过、2 项失败**；两项失败分别是旧计时测试约 7ms 的平台抖动，以及旧价格意图模型把“金额最大”解析为 `amount_desc` 但未填写 `aggregation`。两者涉及的文件均未在本次改造中修改；对应意图测试单独复跑曾通过，属于既有非确定性检查，不计入六工具测评成绩。

### 5.2 真实模型 + 固定假工具

固定条件：

- 模型：`deepseek-v4-flash-vision-exp`
- 温度：0
- 单轮，无历史输入
- 固定系统提示词和六个独立业务工具 schema
- 工具返回完全固定，不连接 MySQL 或 Milvus
- 16 个用例，每个重复 5 次

用例组成：6 个单工具（逐条覆盖六条业务线）、2 个独立多工具、2 个结果依赖、4 个澄清/不支持（包括项目名称和采购人边界）、2 个空结果/工具失败。

六工具基线以 `deepseek-v4-flash-vision-exp` 重复执行5轮，结果为 **80 / 80 通过**。六个单工具类别为30/30，独立多工具为10/10，结果依赖为10/10，澄清/不支持边界为20/20，空结果/工具失败为10/10。测量项为工具选择、参数、顺序、停止状态和失败分类；不对自由文本或推断质量评分。

详细机器可读结果：`test_report/unified_model_eval.json`。

### 5.3 真实基础设施

- 真实 Milvus、Embedding、Reranker 和 RAG 链路已通过；问题“公开招标的适用条件是什么？”完成 1 次主 Agent 调用、1 次 `knowledge_qa` 工具调用和确定性引用发布。
- MySQL `192.168.10.120:3306` 当前连接超时，因此企业、处罚和中标三个真实 SQL 工具尚未完成本轮联调。该项记录为基础设施前置条件不满足，不计入模型编排得分。

## 6. 配置与回滚

默认：

```text
AGENT_EXECUTION_MODE=unified
```

显式回退：

```text
--execution-mode hybrid
--execution-mode legacy
```

旧 Router、静态路径和受约束 ReAct 实现未删除。回滚不会要求恢复代码。

## 7. 下一阶段讨论边界

当前基线已经把“模型能否正确选择动作”和“数据服务能否正确返回”拆开测量。后续若开放推断，应一次只增加一种能力，并新增对应的可判定测评项。首先需要决定的不是让模型写多长的答案，而是哪些跨工具关系允许成为可发布断言，以及这类断言由什么证据和程序规则验收。
