## 输入预算调整（用户已批准并完成）

### 为什么调整

这是修复正常请求被误拦，不是扩大检索数量或延长答案。原来用 16,000 字节统一限制外层调度和 RAG 作答，但完整 RAG 正常输入就可能超过 27,000 字节。模型必须先读到资料，才能把它提炼成短答案。

用户提供的 book1 文件共 316 个切片，最长 2,000 字符，无超长切片。取格式化后最大的五片，普通短问题的完整输入为 31,892 字节；用 4,000 个常见汉字模拟长问题时为 43,862 字节。因此先采用 48,000 字节，并保留超限检查。这是本文件下的容量验证，不保证所有语料和所有字符组合都能容纳。

### 怎样生效

- `AGENT_MAX_INPUT_BYTES=16000`：外层路由、调度继续使用原额度。
- `AGENT_RAG_MAX_INPUT_BYTES=48000`：完整 RAG 作答使用独立额度，允许环境变量覆盖，必须大于零。
- 模型用途由程序创建模型时指定，不由提示词或用户输入指定。不修改共享模型或请求上下文的额度，避免并发串用。
- 模型调用次数、工具次数、超时、取消、输出 token 限制继续共享原有预算。较大的输入额度不代表可以多调用几次，也不代表答案可以无限变长。
- 对完整 JSON 请求体按 UTF-8 字节计数；不是供应商上下文 token 上限，也不等于精确费用预算。
- 没有通过删片段、截断原文或额外摘要来规避容量问题。重启正在运行的助手后读取新配置。
