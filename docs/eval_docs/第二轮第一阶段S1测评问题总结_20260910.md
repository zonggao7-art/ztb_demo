## 三、异常耗时的证据

正式运行的 200 题严格按题集顺序逐题执行。端到端耗时从调用 `knowledge_qa` 开始，到检索和回答全部完成为止。

| 统计项 | 结果 |
|---|---:|
| P50 | 8.495 秒 |
| P95 | 38.521 秒 |
| P99 | 111.135 秒 |
| 最慢一题 | 253.165 秒 |
| 超过 20 秒 | 31 题 |
| 超过 30 秒 | 20 题 |
| 超过 60 秒 | 5 题 |
| 超过 120 秒 | 2 题 |

最慢的 5 题如下：

| 题号 | 耗时 | 回答模型输入 Token | 回答模型输出 Token | 最终可见回答字符数 |
|---|---:|---:|---:|---:|
| q085 | 253.165 秒 | 4955 | 7796 | 113 |
| q098 | 142.392 秒 | 4498 | 789 | 340 |
| q137 | 111.135 秒 | 5734 | 224 | 214 |
| q020 | 83.907 秒 | 5586 | 2124 | 2989 |
| q195 | 75.779 秒 | 5333 | 1816 | 162 |

q085 只返回 113 个可见字符，却产生了 7796 个输出 Token；q195 也只有 162 个可见字符，却产生了 1816 个输出 Token。这说明模型在可见答案之外消耗了大量输出 Token，与隐藏推理的表现一致。200 题中，回答模型输出 Token 与耗时的相关性明显高于输入 Token 或检索材料长度。

## 四、对 OpenRouter 原因的判断

本次回答模型配置为 `deepseek/deepseek-v4-flash-0731`，接口地址为 OpenRouter。2026-09-10 调查时，OpenRouter 的模型信息显示该模型默认启用推理，默认强度为 `high`。项目当前代码只在接口主机名恰好为 `api.deepseek.com` 时自动关闭 DeepSeek 思考；使用 `openrouter.ai` 时不会进入这段处理。因此，**OpenRouter 下默认开启推理是当前证据最充分的主要原因**。

OpenRouter 默认会在多个供应商之间选择，并允许失败后换用其他供应商。不同供应商的排队、生成速度和失败后重试，可能解释 q098、q137 这类输出不算特别多但耗时很高的题。因此，**OpenRouter 路由是可能的次要原因**。

同一天排查时，对 OpenRouter 公共查询接口做了 8 次不调用模型的往返测试，中位数约 1.324 秒，最大约 2.952 秒。这个事后测试不能代表正式运行当时的网络状态，但它说明单纯的本地到 OpenRouter 网关往返，无法独自解释 111 至 253 秒的慢题。
