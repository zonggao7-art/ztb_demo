# 一轮测评工作总结报告

整理日期：2026-09-08。依据本目录中的一轮报告、评分汇总和原始回答记录整理；本次未重新调用模型测评。文中的模型名称、成绩和费用均沿用当时记录。

**一轮测评的主要成果，是为“选哪个模型来回答问题、采用哪套提示词”提供了数据依据，并把回答质量、等待时间、使用成本和失败情况放在一起比较。** 这些结果可以支持二轮确定一个固定的回答模型，但不能说明检索已经优化完成，也不能保证更换资料和检索方式后，模型选择仍然不变。

## 一、一轮测评解决了什么问题？通过哪些指标反映？

### 1. 在相同资料下，哪个模型更适合回答业务问题？

一轮把检索结果提前保存下来，再让不同模型根据相同的问题和资料作答。这样，比较的是各模型使用这份资料回答问题的表现。

共比较了 5 个候选模型：`deepseek_v4_flash`、`hy3`、`minimax_m3`、`qwen3.5_9b`、`glm_z1_9b`。按旧报告分组，三个大模型使用 1,000 条主实验记录，两个小模型使用 200 题子集，各次实际完成和评分数量略有不同。大、小模型的总分不能直接混成一张排名表。

判断模型是否合适，主要看下面几个问题：

| 要解决的问题 | 用哪些指标反映 | 能帮助判断什么 |
|---|---|---|
| 回答有没有依据，是否答对、答在点上？ | 忠实度、回答相关性、回答正确性 | 模型的回答质量是否满足要求 |
| 用户需要等多久？ | 首 token 时间、总时长、P95 时长 | 开始输出和完成回答分别有多快，较慢请求要等多久 |
| 使用起来贵不贵？ | 输入／输出 token、估算费用 | 回答质量对应的调用代价 |
| 能否正常交付回答？ | 失败率、拒答率，并核对原始回答 | 是否出现报错、拒答或没有答案的情况 |
| 面对复杂题是否容易掉分？ | 单跳／多跳分组成绩及分差 | 哪类问题更容易暴露短板 |

以下是 **v2 提示词下，三个大模型的部分结果**，便于直观看到取舍：

| 模型 | 忠实度 | 回答相关性 | 回答正确性 | 平均总时长 | 1,000 条记录的生成费用估算 |
|---|---:|---:|---:|---:|---:|
| deepseek_v4_flash＊ | 0.748 | 0.751 | 0.752 | 3.87 秒 | 2.45 元 |
| hy3 | 0.731 | 0.704 | 0.720 | 4.77 秒 | 1.70 元 |
| minimax_m3 | 0.702 | 0.757 | 0.728 | 9.67 秒 | 3.61 元 |

＊旧报告将 DeepSeek 标记为与评分模型同源，成绩可能受到评分偏好的影响。费用只反映当时配置下的生成阶段估算，不含检索、建库和 Ragas 评分，也不是当前价格。

**得到的判断：** 在这组三个大模型的汇总结果中，DeepSeek 的忠实度、正确性和平均完成速度领先；HY3 的估算费用更低；MiniMax 的回答相关性略高。旧报告因此把 DeepSeek 列为大模型选型的优先参考，而不是所有指标都第一的唯一选择。[质量结果](D:/DEMO/zhaotoubiao_demo_copy/first_round_eval_data/scores_v2/v2_report/comparison_v2_big.md)、[速度与费用](D:/DEMO/zhaotoubiao_demo_copy/first_round_eval_data/scores_v2/v2_report/comparison_v2_perf_cost.md)

### 2. 更换提示词，能不能改善回答？

一轮内部还比较了 v1、v2 两套提示词。**这里的 v2 仍属于一轮工作，不是第二轮测评。** 该实验保持问题和检索结果不变，比较同一模型更换提示词后的表现。

主要看三项回答质量分，同时观察答案长度、输出 token 和耗时，判断改善有没有额外代价。

旧对照报告按共同题目比较后显示：

- 5 个模型的忠实度均提高，说明回答整体上更贴近所给资料。
- 4 个模型的回答正确性提高，Qwen 略有下降，说明提示词改动不是对所有指标都有效。
- 平均答案长度缩短约 42%～68%，但两个小模型的输出 token 总量增加，说明“答案更短”不等于“调用更省、更快”。

**得到的判断：** v2 提示词有改善回答依据性的价值，可以作为后续配置的参考；评价提示词时，需要同时看质量和代价。[提示词对照报告](D:/DEMO/zhaotoubiao_demo_copy/first_round_eval_data/scores_v2/v2_vs_v1_report.md)

### 3. 选型时，除了质量分，还需要关注哪些实际问题？

一轮记录了等待时间、费用、失败情况，以及单跳和多跳题的表现。这让选型不再只看“哪个模型分数高”，也能看到慢请求、调用代价和复杂题短板。

例如，一轮小模型结果中，Qwen 的忠实度和正确性较好，但耗时和失败情况也需要一起考虑。单跳／多跳分组能帮助发现复杂题掉分，却不能单独说明原因：可能是资料没有找全，也可能是模型没有用好已经找到的资料。

**得到的判断：** 一轮形成了一套可以继续使用的比较方法和结果记录，为后续选型与问题排查提供了基线。

## 二、一轮测评有哪些核心指标？

### 1. 回答质量：最核心的三项指标

这三项由 Ragas 调用评分模型打分。分数通常在 0～1 之间，越高表示该项表现越好；**0.75 分不等于 75% 的问题完全答对。**

| 指标 | 通俗理解 | 使用时要分清什么 |
|---|---|---|
| **忠实度 Faithfulness** | 回答中的说法，能不能从提供的资料中找到依据？ | 有依据不代表资料本身正确、有效，也不代表回答完整 |
| **回答相关性 Answer Relevancy** | 用户问的事情，回答有没有围绕它展开？ | 答在点上，不等于说法正确或所有要点都答全 |
| **回答正确性 Answer Correctness** | 回答与参考答案相比，内容对不对、要点是否一致？ | 依赖参考答案的质量；参考答案有误，评分也可能失真 |

例如，用户问“报名截止时间是什么时候”：回答一大段投标流程，可能有资料依据，却没有答在点上；回答了一个日期，可能很相关，但日期未必正确。三项指标需要一起看。

### 2. 等待时间、费用和稳定性：决定是否好用

| 指标 | 通俗理解 | 怎么看 |
|---|---|---|
| **首 token 时间 TTFT** | 调用模型后，多久开始收到 token？ | 通常越短越好；不直接等于完整 Agent 向用户展示第一段有效答案的时间 |
| **总时长** | 生成调用从开始到结束用了多久？ | 看平均值，也看较慢请求；这是生成阶段记录，不是完整系统耗时 |
| **P50／P95／P99 时长** | 分别有 50%／95%／99% 的请求，在这个时间内完成 | 例如 P95 为 10 秒，表示约 95% 的请求不超过 10 秒；不是最长耗时 |
| **估算成本** | 按记录的 token 和当时配置的单价，估算花了多少钱？ | 比较相同题数或每题费用；不能用大模型 1,000 题总费用直接对比小模型 200 题总费用 |
| **失败率** | 旧测评记录中，有多少调用被判定为失败？ | 越低通常越好，但原有统计存在漏记空答案的情况，不能单独作为成功交付证明 |
| **拒答率** | 有多少回答被记录为拒答？ | 不是越低越好：资料不足时应该拒答，资料充分时不应误拒答 |

### 3. 辅助指标：解释分数背后的原因

| 指标或记录 | 主要用途 |
|---|---|
| **输入／输出 token 总量** | 解释调用费用和输出规模；token 是模型处理文字的计量单位，不等于中文字数 |
| **输出吞吐量，token／秒** | 观察生成输出的速度；不能替代总时长 |
| **平均答案长度** | 观察回答是否过长、提示词是否改变表达方式；长短本身不代表质量高低 |
| **单跳／多跳成绩及分差** | 比较较直接的问题与需要关联多处信息的问题；采用旧题集的分类标签 |
| **评分失败数** | 有多少条记录未能完成评分；评分失败与模型回答失败是两回事 |
| **实际样本数、自评标记** | 说明每个成绩对应多少记录，评分模型是否与被评模型同源，避免误读比较结果 |

上述字段可在[一轮 v2 评分汇总样本](D:/DEMO/zhaotoubiao_demo_copy/first_round_eval_data/scores_v2/deepseek_v4_flash_summary.json)及[一轮 v1 分组报告](D:/DEMO/zhaotoubiao_demo_copy/first_round_eval_data/scores/v1_report/comparison_v1.md)中查到。

## 三、一轮结论的使用范围

**可以支持：** 根据当时成绩选择一个后续实验使用的回答模型，参考 v2 提示词，并沿用已有的质量、耗时、成本和稳定性记录方式。

**尚未解决：** 哪种检索方式最好、必要资料是否全部找齐、数据治理后哪个模型最合适，以及完整 Agent 的工具选择、多轮执行和故障恢复是否可靠。一轮主要比较固定检索结果下的生成表现，没有完成这些问题的对照验证。

一轮主报告也没有把“检索召回率、必要资料全部找齐率”列为正式核心指标。三项回答质量分可以帮助发现回答问题，但不能直接当作检索成绩。

本次整理还核对了几项会影响结果解读的事实：

- **样本数不完全一致。** 主实验有 1,000 条记录、998 个不同问题；小题集有 200 个不同问题。不同模型、不同提示词版本的实际回答和有效评分数量有所不同。
- **旧失败率漏记了部分空答案。** 当前保存的 v2 原始回答中，MiniMax 有 1 条空答案，GLM 有 6 条空答案，但两者汇总中的失败数均为 0。因此不能把“失败率为 0”写成“全部问题都成功交付”。[MiniMax 原始记录](D:/DEMO/zhaotoubiao_demo_copy/first_round_eval_data/model_results_v2/minimax_m3.jsonl)、[GLM 原始记录](D:/DEMO/zhaotoubiao_demo_copy/first_round_eval_data/model_results_small_v2/glm_z1_9b.jsonl)
- **评分配置的旧记录有差异。** 不同报告分别出现过 `deepseek-chat` 和 `deepseek-v4-flash` 的裁判名称；本文沿用各报告的成绩，并保留同源评分提示，不把它们视为已经核实完全一致的配置。[v2 比较报告](D:/DEMO/zhaotoubiao_demo_copy/first_round_eval_data/scores_v2/comparison.md)、[目录根部旧报告](D:/DEMO/zhaotoubiao_demo_copy/first_round_eval_data/comparison.md)

二轮可以据此固定回答模型，再比较不同检索配置。届时得到的是“检索变化对资料和该模型回答效果的影响”；如果还要确认改造后哪个模型最合适，则需要另做候选模型比较。
