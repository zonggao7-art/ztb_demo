# 第二轮旧 S1、新 S1、S2、S3、S4 对比报告

> 报告日期：2026-09-12
> 本报告基于五次已经完成的正式测评，只整理本地结果，不重新调用回答模型或 Ragas。

## 一、五个阶段分别代表什么

这条路线的分析顺序是“旧 S1 → 新 S1 → S2 → S3 → S4”，但不是运行日期顺序。S4 于 2026-09-11 完成，新 S1 是在 2026-09-12 回头补测的。新 S1 的作用是用官网回答模型和最终冻结源码，重新建立可信的稠密检索基线。

| 阶段 | 运行编号 | 相比前一步的主要变化 | 最终检索流程 |
|---|---|---|---|
| 旧 S1 | `s1_20260910_formal_02` | 最初历史基线 | 稠密 30 条 → 余弦阈值 0.45 → Top-5；回答模型走 OpenRouter |
| 新 S1 | `s1_20260912_formal_03_official` | 改用 DeepSeek 官网回答模型，并按最终源码补测 | 稠密 30 条 → 余弦阈值 0.45 → Top-5 |
| S2 | `s2_20260910_formal_01` | 加入稠密与稀疏混合检索，并用 RRF 合并排序 | 稠密 30 + 稀疏 30 → RRF Top-30 → Top-5 |
| S3 | `s3_20260911_formal_02` | 在 S2 后加入重排模型 | 混合检索 → RRF Top-30 → 重排 Top-5 |
| S4 | `s4_20260911_formal_01` | 在 S3 后加入动态过滤 | 混合检索 → RRF → 重排 Top-5 → 动态过滤 |

五次运行均使用同一份 200 题题集，采集均为 200/200，四项质量评分均为 800/800。

Ragas 的 Context Recall 判断“最终资料是否能支持参考答案”。精确 chunk 命中则直接核对题集标注的 chunk 编号。旧 S1 的精确结果由旧、新 S1 的 200 题逐题配对结果回算。

| 指标 | 旧 S1 | 新 S1 | S2 | S3 | S4 |

| Micro Recall（全部标准 chunk 合并） | 66.30% | 66.30% | 82.22% | 92.96% | 92.96% |

最明显的检索提升发生在 S1 → S2 和 S2 → S3。S3 → S4 的四项精确命中指标完全不变。

## 六、S4 动态过滤的实际作用

S4 在 200 题中改变了 17 题，未改变 183 题；从 1,000 条重排后资料中删除 53 条，没有删除标准 chunk，也没有产生空检索。

本次 200 题全部落在 0.40 高置信阈值，0.45 和 0.50 两档没有真实题目覆盖。因此，S4 结果只能说明当前题集上的 0.40 过滤表现，不能证明三档规则都有效。

对发生过滤的 17 题，Context Precision 增加 2.25 个百分点，Answer Correctness 下降 3.56 个百分点；这比只看 200 题均值更能反映动态过滤的实际影响。

## 七、结论与人工决策依据

1. **旧 S1 应继续保留为历史记录，但不应再作为速度基线。** 它的检索命中与新 S1 相同，主要问题是回答模型调用路径导致的长尾延迟。
2. **新 S1 是当前更可信的稠密检索基线。** 它修正了耗时异常，并与后续阶段使用相同的官网回答模型。
3. **S2 在本次数据中呈现出较小的速度代价。** P95 增加 5.50%，同时四项质量指标和四项精确命中指标全部提升；是否将其视为最合适的投入产出关系，仍由人工决定。
4. **S3 提供了第二轮主要检索收益，也承担了主要成本。** 重排显著提高 Context Precision 和标准 chunk 命中率，但明显增加查询耗时和重排处理量。
5. **S4 的效果是混合的。** 它没有继续提高精确命中，Context Precision 上升，其他三项质量分下降，同时查询耗时反而降低。动态过滤是否保留，需要根据“资料更精简”是否值得 Answer Correctness 的下降进行人工判断。
6. **若只比较最终 S4 与新 S1，完整检索链路仍然取得明确净收益。** 四项质量指标均高于新 S1，P95 保持在 3 秒以内，但需要承担重排调用和处理量。

## 八、比较边界

- “旧 S1 → 新 S1 → S2 → S3 → S4”是分析顺序，不是实际运行日期顺序。
- 旧 S1 → 新 S1 同时存在调用平台、回答模型标识和源码版本差异。
- 新 S1 → S2 使用相同题集和模型配置，但源码快照存在 14 个文件差异。
- S3、S4 都设置了每题至少间隔 10 秒启动；等待时间不计入 P50/P95。不同运行时间的网络和供应商负载仍可能影响耗时。
- Ragas 四项质量分由模型裁判产生，存在评分波动；精确 chunk 命中用于补充判断检索变化。
- 回答模型 Token 是 API 实际值；查询嵌入和重排输入 Token 是估算值，三者必须分开解释。
