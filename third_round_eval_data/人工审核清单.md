# 第三轮题集人工审核清单

当前280道主集和24个可靠性场景已由 `zz` 于2026-09-12审核通过。逐题状态、审核人、日期和备注保存在对应JSONL记录中，整批覆盖范围与内容哈希保存在 `human_review_record.json`。

## 一、建议审核顺序

1. **35道结果依赖题**：逐题确认项目只返回一个可用中标供应商，后续工具和 `prior_verified_result` 字段合法。
2. **60道负向题**：确认 `clarify` 与 `unsupported` 的边界、`missing_fields` 以及零外部 I/O 要求。
3. **40道SQL＋RAG题**：确认两个任务确实互不依赖、RAG子问题是本轮原文的完整连续片段。
4. **35道独立多动作题**：确认所有任务都来自用户明确要求，且不同执行顺序均可接受。
5. **40道SQL单工具题**：对照 SQL 快照审核有结果、无匹配和空字段案例。
6. **70道RAG锚点**：主要复核统一 Agent 动作与问题绑定；RAG内容金标准沿用S4审核结果。
7. **24个可靠性场景**：确认故障注入、取消时点、并发方式和恢复断言与当前测评程序实现一致。

## 二、每道主集必审字段

- `query` 是否自然、无模板拼接歧义，并且不泄露答案；
- `category`、`subcategory` 和风险等级是否合理；
- `expected.action_graph` 是否完整，是否存在漏工具或多余工具；
- 当前输入参数是否逐字来自本轮问题；
- 依赖参数是否只来自同请求内上游已核验结果；
- 无依赖动作是否允许任意拓扑顺序，不能误写成固定线性顺序；
- `allowed_finish_status` 是否与真实工具状态一致；
- `expected_missing_fields` 是否足以形成可执行的新问题；
- SQL真值引用或RAG金标准引用是否正确；
- 指标列表是否覆盖该题的主要风险；
- 正向题是否完全自包含，没有依赖历史对话；
- 负向题是否明确要求零业务工具调用。

审核后才可把该题的 `review_status` 从 `pending_human_review` 或 `rag_gold_inherited_agent_case_pending_review` 改为 `human_approved`，并记录审核人、时间和备注。不要只批量替换状态而没有逐题记录。
